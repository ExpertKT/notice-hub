# 群务台微信小程序

原生 WXML / WXSS / JS 工程。待办、对话、地图三个底部入口，连接设置独立成页。不需要 npm 安装或构建。

## 导入

1. 打开微信开发者工具，选择「导入项目」，目录选本 README 所在的 `miniprogram` 文件夹，不选仓库根目录。
2. `project.config.json` 里填的是演示用 AppID `wx073438c137527cdf`，只能在本机开发者工具里打开模拟器；要上传、真机预览或自动化，换成本人有开发权限的 AppID。AppID 可在 `mp.weixin.qq.com` 免费注册个人主体取得。用 `touristappid` 这类占位值时，工具会报 `code: 10`「不存在此 AppID」。
3. 首次进入会打开连接设置。服务地址和访问令牌均为空，不会自动连接任何实例。
4. 从自己的群务台服务取得地址和访问令牌，填写后点「保存并检查连接」。只有收到 `/api/overview` 的有效响应，页面才显示「已读到服务总览」。仅点「保存并看待办」只保存信息，不代表连通。
5. 暂不连接可点「看看示意地图」。之后各屏右上角都能重新进入连接设置。

开发者工具安装路径为 `F:\wxdevtools`。工程将 `urlCheck` 设为 `false`，只用于本地开发；不会替代微信后台的正式域名配置。

## 连接配置

- 服务地址只填协议、域名或 IP、可选端口，例如本地开发地址 `http://127.0.0.1:8766`。不要添加 `/api`、其它路径、查询参数或账号密码；该地址只是格式示例，代码不预填。
- 所有请求都携带 `X-Token`。访问令牌保存在当前小程序设备的 storage 中，键为 `noticehub.connection`；未加密，不写日志，也不随工程提交。
- 只有对话操作会修改服务端数据。使用自己的测试服务，不要把带写操作的演示连到生产数据。
- 对话及今况需要服务端启用 `NOTICEHUB_AGENT_SHELL=1`，并按群务台现有方式配置模型。客户端不替服务端启用这些能力。

## 页面与接口

| 页面 | 接口 | 行为 |
| --- | --- | --- |
| 待办 | `GET /api/tasks` | 显示待确认、今天、本周、之后、已完成；空分组不显示。支持刷新、下拉刷新和停止加载。 |
| 待办勾选 | `POST /api/tasks/<id>` | 每张卡片带「完成」，已完成分组带「恢复」，body 为 `{"action":"done"}` 或 `{"action":"reopen"}`。服务端确认后才重读列表；没确认时保留原列表并说明下一步。 |
| 待办今况 | `GET /api/agent/brief` | 显示 `sentence`。失败只影响今况，不阻断待办。 |
| 对话 | `POST /api/agent/chat` | JSON 为 `{session_id,text}`；首次会话 ID 为空，之后采用服务端返回的 ID。每次最多 500 字。返回的 `trace` 以虚线小字显示在回复下方：读了几件待办、打算怎么做、调了哪个工具、成没成。 |
| 连接设置 | `GET /api/overview` | 保存后检查服务总览，列出返回的通道状态。 |
| 地图 | `GET /api/tasks` | canvas 按 `assets/campus.js` 里的 27 个校区地点画方块，北向上，可选地点与层数。按待办标题里的楼名或别名标出地点与件数（文字匹配，不是定位）。 |

连接检查最长等待 45 秒，待办和今况各 20 秒，对话 300 秒，等待时显示已等秒数。均可停止等待，离开页面也会取消客户端请求。停止等待不保证服务端撤销操作；若刚发过对话，先到待办页刷新确认，再决定是否重发。失败会保留输入，不自动重发。

## 错误与下一步

- 没有连上：检查电脑端服务、网络、防火墙、地址和微信域名校验；页面提供重试或修改连接入口。
- HTTP 401 / 403：显示「访问令牌未通过」，打开连接设置核对令牌；403 也可能由服务端其它访问限制引起，仍需检查电脑端状态。
- HTTP 404：核对地址及服务端能力开关。
- 其它 HTTP 4xx：显示状态码，核对输入及地址后再试。
- HTTP 5xx：显示状态码，检查电脑端运行状态后再试。
- HTTP 200 但不是 JSON 对象、待办缺少分组、对话返回 `ok:false`：显示对应错误，不当作读取或发送成功。

## 真机预览前置条件

1. 换成有开发权限的小程序 AppID，开发者工具登录相应账号，手机微信也有项目预览权限。
2. 正式访问需要可被手机访问、证书有效的 HTTPS 服务域名，在微信公众平台配置 `request` 合法域名。按微信当前要求处理域名备案、证书、端口及后台权限。
3. 手机里的 `127.0.0.1` 指向手机自身。局域网调试须用电脑局域网地址，确保同网段、服务监听地址和防火墙允许访问；仍受微信调试模式与域名策略限制。
4. 开发工具中的 `urlCheck:false` 仅是开发选项，不能推断真机或上线后也能访问 HTTP / IP 地址。不通过域名校验的调试方式不要作为交付环境。
5. 不在任何生产实例上试发新增、删除或修改待办的对话。

## 检查

从仓库根目录运行：

```powershell
Get-ChildItem miniprogram -Recurse -File | Where-Object { $_.Extension -in '.js', '.cjs' } | ForEach-Object { node --check $_.FullName; if ($LASTEXITCODE -ne 0) { throw "语法检查失败：$($_.FullName)" } }
node miniprogram/checks/check.cjs
```

行为探针使用内存中的 `wx` 替身，不访问群务台、不修改真实待办。覆盖配置持久化、请求头、HTTP 错误、格式错误、取消、待办解析、勾选完成与恢复（含连点只发一次、服务端未确认时保留列表）、对话规划过程、待办地点标记、对话及设置离页后旧响应隔离。探针通过不代表小程序已在微信运行。

## 已知限制与本次验证

- 校区数据抄自服务端 `noticehub/application/campus.py` 的 `DEFAULT_POIS`：27 个地点，含名称、别名、米制中心坐标（x 向东、y 向南）、层数、类型。服务端不通过 HTTP 暴露 POI，只能内置一份；`campus.py` 增删地点时要同步 `assets/campus.js`。坐标无独立测绘，只有中心点，画出的方块边长只表示观感，不是真实占地；无地图接口、定位或导航，也没有路线。
- 待办地点按楼名与别名匹配，楼名表按长度倒序、命中即停（「11号楼」不会被「1号楼」抢走）。待办里有地点字段之前，这只是文字匹配。
- 待办可勾选完成、从已完成恢复；仍无翻页，沿用服务端分组数量上限。
- 对话仅在本次页面运行中保留最近 40 条；改变连接后清除会话，不加载历史消息。
- 页面跟随系统明暗外观，使用暖纸底、橄榄绿和衬线标题。原生导航栏与底栏通过 `theme.json` 跟随系统；地图主题变化时重绘。四页各有自己的深色样式块。
- 可点控件高度不小于 `88rpx`；`.small` 按钮同时锁定 `min-width` 与 `min-height` 为 `88rpx`。正文与标题超长时折行不截断，只有 canvas 上的楼名超过 8 字截为 7 字加省略号。
- 真机未验：本机只在开发者工具模拟器里跑过（`cli.bat auto --auto-port 9420` + `ws://127.0.0.1:9420` 的 `App.captureScreenshot` 出图），没在手机上跑过；深色模式没在模拟器里切过主题，只有样式断言。
- 访问令牌 token 存在设备 storage 中，未加密；能读取该 storage 的人可能取得令牌。
