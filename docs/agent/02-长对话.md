# 待办对话：长对话

这一份只覆盖待办页对话框。浮球、托盘、安装、设置、托管、更新仍然不进这趟对话。

## 链路

浏览器不拿模型钥匙，也不自己决定改哪一条。

1. 页面把这句话和 `session_id` 交给 `POST /api/agent/chat`。
2. 服务端按会话留下最近 12 轮「你说 / 它说」，并附上当前待办的 id、标题、状态、截止时间。
3. 用设置里已经配好的 OpenAI 兼容接口发这一串。模型只返回一句中文，外加最多 3 个待办动作。
4. 动作由服务端执行，走现成的待办用例。群里的和用户自己说的都在这一张表：新建、改标题、改期、完成、忽略、确认、稍后、恢复、置顶、紧急、删除、清空已完成。执行结果再送回模型，最多两轮；如果说记下了却没调用，再补一次。然后把最后一句中文交回页面。
5. 有写操作时页面再拉一次待办，时间轴按已有的淡出和补位来画。
6. 刷新页面时，最近 12 轮先备好，对话框仍停在未唤醒。点进输入框后，记录才随着输入条一起出现。发出去的那句马上出现，回复写上来之前，助手那边显示「正在回复」，三个点轮流亮。

没配钥匙、也不是本机 Ollama 时，这个接口回答 `fallback`，页面仍走原来的固定说法。模型报错时不退回固定说法，避免同一句既改了数据又再改一次。

这个地址和今况一样，只有 `NOTICEHUB_AGENT_SHELL=1` 才挂上，不写进 `routes.py` 的静态表。

## 技术要点

- 会话只放在进程内存里。重启即丢。不把群消息原文送进对话，只送待办列表，并标明这条是群里的还是手动记的。
- 群待办和用户自己说的事是同一张表。说出一件要做的事就 `create`；查只回答、不写；改标题用 `rename`，改时间用 `reschedule`；完成、忽略、置顶、紧急走原来的动作。
- 还开着的群待办不能直接删除，只能忽略。手动记的和已经完成的才能删除，而且要下一句确认。
- 不使用各家不一样的工具调用字段。模型在正文里给 JSON：`{"say","calls"}`。正文不是 JSON 时，整段当作闲聊，不改数据。
- 模型若说「记下了」或「只管群待办」却没有调用，服务端再要一次 JSON。第二次仍没写上，回复改成「还没写进待办」，不把口头答应当成已经保存。
- `task_id` 可以是数字，也可以是标题里的几个字。对上 0 条或不止 1 条就停，一条都不改。
- 删除和清空已完成第一次只记「待确认」，不落库。下一句模型对同一操作带 `confirm: true` 才执行。第一句就带 `confirm` 的，当成还没确认。
- 单次模型请求最多 25 秒，一轮用户消息最多两跳；嘴上答应但没调用时再补一跳。页面等待 70 秒。
- 钥匙留在服务端的 `Authorization` 头里，响应和日志都不回传钥匙。
- 以后要加别的数据，在 `calls` 里加新的 name，由服务端执行。这一轮只做待办这一张表的增删查改。
