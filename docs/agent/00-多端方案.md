# 智能体壳：多端同一句话

分支 `agent/unified-shell`，从 `origin/main` 的 `f268cd2` 拉出。不合并进 `main`，也不改 `main` 上的路由、页面和包。以后若接入，按插件接：默认关闭，关掉之后现有待办台与现在一字不差。

这一份只定结构和界面。不改 `page.html`，不加接口。

## 现在在跑的是什么

电脑上有两个进程。`QQ-Notice-Hub.exe` 管托盘和看门狗。服务进程听 `8766`（网页、手机、日历）和 `8765`（NapCat 上报）。数据在本机 `data/` 的 SQLite。四个来源进同一条链：收消息、攒批、摘要、拿不准的进收件箱，确定的变成待办，再推送。

人看到的表面有四块，数据是同一份：

| 表面 | 现在怎么画 |
|---|---|
| 桌面网页 | `noticehub/web_static/page.html`。顶上浮岛：品牌、四个页签（待办、最近推送、收件箱、设置）、铃铛。窄于 760px 时浮岛落到屏幕底部 |
| 手机 App | WebView，打开的就是上面那一页。扫码或 6 位码配对。App 自己不存待办 |
| 桌面浮球 | `noticehub/floatball_page.py` 另写一份 HTML。收起 72×72，展开 380×600。规格在 `docs/qa/浮球设计规格.md` |
| 托盘 | 启动器。看服务在不在，不画待办 |

配色、字号、间距、动效已经写在 `docs/ui-taste.md`。青绿强调、纸色表面、状态必须带文字。本方案沿用这套，不另起一套「智能体紫」。

页面向导里已有一句「建议让 agent 来装」。那是让外面的编程助手帮忙装软件，不是本产品的智能体。两件事分开，界面上不要混用这个词。

## 智能体要显出来的四点

产品已经在替人看群、挑通知、拿不准就停下来。缺的是让人在每一端看见同一件正在发生的事。

1. **它先做，再给你看。** 首屏第一句是它刚刚做成的事，或它卡住的事。例如「今天 3 件待办，1 条还要你确认」。不是输入框，不是「有什么可以帮你」。
2. **拿不准就问一句。** 收件箱里的待确认就是这一问。问句和按钮用现有动作：确认、忽略、稍后。不新开一轮自由对话。
3. **工具是它用过的来源，不是一排可点的技能卡片。** 这句话旁边标来源（QQ / 微信 / 钉钉 / 学习通）和置信。设置页继续管接入，不搬进这句话里。
4. **记忆就是这台电脑上的库。** 三端读同一句，因为句子由服务算出来。手机和浮球不各自编文案。

## 三端一张皮，三种密度

同一组件，名字叫「今况」。服务给出一句、一个主动作、最多三条相关待办。三端只改密度。

| 端 | 今况放哪 | 密度 |
|---|---|---|
| 桌面 | 浮岛下面一条，高度约一行标题加一个按钮。四个页签不动 | 句子 + 主动作。点句子展开那三条 |
| 手机 | 同一条，贴在待办列表上方。底部页签保持现在的 48px | 与桌面同一句。按钮保持 44px 以上 |
| 浮球 | 收起态用这句里的数字做角标，摘要用这句的前两行。展开态先画今况，下面才是那三条 | 不维持第二份任务排序规则 |

托盘不画今况。推送正文若提到「还要你确认」，用今况的同一句，避免手机通知和网页各说各话。

视觉只动现有 token：`--paper`、`--ink`、`--muted`、`--line`、`--teal`、`--amber`、`--red`。今况是一条表面，不是头像、不是光球、不是渐变边框。紧急和失败继续带文字，不单靠颜色。动效遵守 `docs/ui-taste.md`：只在今况从无到有、或主动作完成时动 `transform` / `opacity`。

## 结构怎么改，才还能拆成插件

今况的句子放在一个纯函数里，读现有的概览、待确认条数、最近一条推送、以及网页进程里已经有的任务槽快照。不新建表，不改待办状态机。

建议落点，等这一份定了再写代码：

| 块 | 落点 | 关掉插件时 |
|---|---|---|
| 句子 | `noticehub/application/agent_brief.py` | 没人调用 |
| 只读接口 | `GET /api/agent/brief` | 开关关闭时不注册这条路由，`routes.py` 与现在相同 |
| 桌面和手机 | `page.html` 里一块 `#agent-brief`，由开关决定是否渲染 | 不渲染，四个页签仍是现在的位置 |
| 浮球 | 展开页改为请求同一接口 | 继续用现在的浮球页 |

开关用环境变量，默认关。名字待定，不放进这一轮的 `.env` 键清单，避免和 `main` 的配置契约搅在一起。

插件边界就这四块。待办、收件箱、日历、设置、配对、更新都不进入插件。

## 接口草样（未实现）

开关打开时，`GET /api/agent/brief` 返回：

| 键 | 含义 |
|---|---|
| `sentence` | 给人读的一句。三端原样显示 |
| `action` | `confirm` / `open` / `none`。`confirm` 时按钮进收件箱第一条待确认；`open` 时按钮去待办 |
| `count` | 句子里的件数，浮球角标用它 |
| `items` | 最多 3 条，每条只有 `id`、`summary`、`deadline`、`source`。字段必须来自现有待办或收件箱，不新造 |
| `updated_at` | 本地 naive 时间的 ISO 字符串 |

鉴权与现有网页相同。没有令牌就是现在的 401。开关关闭时这条路径不存在。

## 这一支接下来的顺序

1. 只加 `agent_brief` 函数和单测。不注册路由。
2. 开关打开才注册 `GET /api/agent/brief`。关掉时 `routes.py` 的条数与 `f268cd2` 相同。
3. `page.html` 加今况，桌面和窄屏各看一次。用浏览器点：句子、按钮、失败时按钮还在。
4. 浮球改读同一接口。收起角标等于 `count`。
5. 按 `docs/ui-taste.md` 第 7 节打分，并留桌面、390px 宽、浮球收起/展开四张截图。不过不合并。

每步单独提交，仍在 `agent/unified-shell`。不推 `main`，不合 `main`。
