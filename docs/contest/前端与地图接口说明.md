# 前端与地图接口说明（给接手的 agent）

这份文档只讲「页面 ↔ 后端」和「地图怎么画」两件事，用来接着改前端与地图功能。所有字段都以代码为准，这里给的是路径与函数名；行号按 2026-11-19 的代码核过，页面还在动，行号对不上就按函数名、选择器或接口路径搜。

## 1. 数据怎么流

```
page.html（页面骨架 + 排版，CSS 全在里面）
  └─ js/trip.js      今日行程：取 /api/agent/plan，决定画地图还是画行程条，再往下画
       ├─ js/map3d.js   有 WebGL 就交给它：楼是真体块、带光、可转视角
       └─ js/campus-osm.js  底图轮廓（校园路网、水面、楼块多边形）与校准参数
  └─ js/notice.js    最近推送、收件箱
  └─ js/settings.js  设置页
  └─ js/announce.js  公告与铃
  └─ js/guide.js     引导浮层（journey / onboarding）
  └─ js/pair.js      配对、二维码
```

智能体对话（读/想/调三步过程、行程、改待办）走 `/api/agent/chat`，答案与调用链一起回来，页面把 `trace` 一条条铺在对话记录区。

## 2. 接口清单

| 方法 | 路径 | 请求 | 响应关键字段 | 代码位置 |
| --- | --- | --- | --- | --- |
| GET | `/api/agent/plan` | 无 | `ok`、`plan`（见下）、`plan.pois[]`、`plan.trips[].line` | `noticehub/webapp.py:4827` → `application/agent_plan.py:102 today_plan` |
| POST | `/api/agent/chat` | `{"text": "...", "session": "..."}` | `ok`、`say`、`trace[]`、`changed` | `application/agent_chat.py:111 chat_turn` |
| GET | `/api/agent/brief` | 无 | 今况简报（浮球与首屏共用） | `application/agent_brief.py:30 agent_brief` |
| GET/POST | `/api/agent/schedule` | 课表文本 / 结构化 | `ok`、`lessons`、`rejected` | `agent_plan.py:182 parse_schedule_text` |
| GET/POST | `/api/agent/routines` | 常做的事 | `ok`、`routines[]` | `agent_plan.py` 里的 routines 读取与保存 |
| POST | `/api/agent/plan`（`action=order`） | `{"date": "YYYY-MM-DD", "order": [标题...], "groups": [[标题...]]}` | `ok`、`order`、`groups`、`plan` | `agent_plan.py:458 save_plan_order`，回给页面的 plan 在 `webapp.py:4894` 重算 |
| POST | `/api/agent/plan`（`action=here`） | `{"x": 380.5, "y": 1101.0}` 或 `{"place": "图书馆"}` | `ok`、`place_id`、`name`、`at`、`x`、`y`、`near`、`plan` | `agent_plan.py:606 save_here` |
| GET/POST | `/api/agent/map/config` | 无 | 各档底图能不能用、key 从哪来、OSM 瓦片源 | `agent_plan.py:824 map_config` |
| POST | `/api/agent/map/keys` | `{"provider": "amap\|baidu\|osm", "key": "...", "secret": "...", "tile": "..."}` | `ok`、`provider`、`config` | `agent_plan.py:858 save_map_keys` |
| GET/POST | `/api/agent/campus/poi` | 自定义地点 `{action, id, name, x, y, kind}`，`action ∈ add/edit/move/hide/unhide/remove`（`agent_plan.py` 的 `_poi_actions` 是唯一白名单） | `ok`、`poi`、`count` | `agent_plan.py:1001 save_poi` |

`/api/agent/plan` 的 `plan` 形状（`agent_plan.py` 的 `today_plan`）：

- `pois[]`：`{id, name, x, y, zone, kind, floors, src}`。坐标是**底图快照的像素**（不是经纬度，也不是平面图坐标——`campus-geo.json` 里的 `from_plan` 才是平面图坐标，两者差一次 `planToSnapshot` 旋转），`src` 取值 `osm / osm-footprint / estimated / unknown`，页面把 `estimated` 画虚线。
- `trips[]`：`{zone, from_place, stops: [...], line: [[x, y], ...]}`。`line` 是后端 `campus_roads.road_line()` 算出来的绕楼折线（`agent_plan.py:160 _attach_road_lines`），同一套快照像素，页面「绕楼」档直接画，「直线」档不用。
- `trips[].stops[]`：`{place_id, place, zone, arrive, why, road}`。`why` 是那一站的排序理由（`trips.py:381 _why`），`road` 见下。
- `trips[].stops[].road`：`{path, degraded, reason}`。`path` 是这一腿贴着路网的折线，`reason` 只有四种取值——`routed`（接上了路网）、`straight`（只画得出两点、且那条直线穿楼或过水）、`no_leg`（这站没有上一站，比如起点）、`missing_data`（缺坐标）。`degraded: true` 只在 `reason=straight` 时为真，页面在站名后面标一行「这一段没接上路网，按直线估的距离」（`js/trip.js` 里搜这句话）。这四种取值由 `application/campus_roads.py:758 road_leg()` 决定，前端不做二次判断。
- `rest[]`：排不进去的事，带原因；页面上折叠成「没说地点，先放着」。
- `here`：用户标的「我在…」，`{place_id, name, at, x, y}`；拖出来的点 40 米内没有楼就是「自由位置」，`place_id` 形如 `here_<x>_<y>`，另带 `near`（最近一栋楼的名字，只作说明，不是落点）。没标就是 `null`，默认起点退回课表最后一节课那栋楼。
- `counts`、`warnings[]`、`lesson_count`、`poi_count`、`path`。

## 3. 地图坐标与校准

- 地点表：`noticehub/web_static/js/campus-geo.json`（27 个内置 POI），字段 `x/y/zone/kind/floors/src`。用户自定义地点存在数据目录的 POI 文件里，`/api/agent/campus/poi` 写入，页面不直接改 JSON。
- 平面图坐标 → 底图快照坐标：`planToSnapshot = {a: 1.006566, b: 0.157187, tx: 58.369, ty: 177.285}`。
- 底图快照 → 屏幕：`calibration.osmToPoi = {sx: 0.8065, bx: 170.4, sy: 1.0382, by: -327.5}`，在 `campus-osm.js` 里。
- 比例：`metersPerPixel = 0.9`。后端算距离用平面单位「1 单位 = 1 米」（`application/trips.py` 里算距离的 `math.hypot`），**别把 metersPerPixel 混进后端**。
- 底图多边形只有 6 栋带名字，其余靠 `campus-geo.json` 的楼名；`src: estimated` 的位置是手摆的（博雅居 `[281,572]`、白云楼 `[480,832]`、马士楼 `[638,843]`、汤湖楼 `[593,926]`、立德楼 `[358,1101]`、立功楼 `[661,1146]`），页面上用虚线标出来，别假装是实测。
- 不接外部地图厂商：OSM/高德/百度三档只在用户配了钥匙时出现，没钥匙就自动收起来。
- 别人接自己的底图：引一段 JS 调 `window.nhMapProviders.register(spec)`，契约写在 `js/trip.js` 里「底图供应商接口（window.nhMapProviders）」那段注释（`:1375-1388` 是契约与内置适配器，外壳给的 `register/get/list` 紧接在后面）。`spec = {id, label, credit, needsKey, init(el, ctx) → Promise<adapter>}`，`ctx = {tile, key, secret, pois, geo, proj}`；`adapter = {kind, toPlan(clientX, clientY), fromPlan(x, y), toScreen(x, y), frame(latlngs), onMove(cb), destroy()}`。**不用实现 `setMarkers`**（同一段注释里写明了：三内置适配器都实现成空函数、外壳也从不调它），楼点和「我在哪」由外壳拿 `toScreen` 自己画在覆盖层上。注册之后底图按钮栏自动多一档（`modeBar`，遍历注册表），坐标系换算由宿主统一做，第三方不用自己处理 GCJ/BD 偏移。完整说明见 `docs/wiki/map-providers.md`。

## 4. 画图的三个模块

`js/trip.js`（8.4 万字节，主力）

- `drawMap(plan)` 是总入口（`:84`）。先量 `#trip-map` 的盒子：
  - 宽度 < 40 → 返回（切页签、收合中，等 `ResizeObserver` 叫醒，见 `bot` 段 `:1784`）。
  - 高度 < 200 → 撤掉 3D 画布、改画横向行程条 `drawStrip()`（`:70`、`:116`）：对话态就是这么来的。
  - 否则交给 `nhMap3d.draw()`；没有 WebGL 就走同文件里的 SVG 兜底。
- 楼名绘制顺序在 `:214` 一带，`NAMED` 名单 `:63`（`ligong/lide/lixing/tuwen/library/boyaju/canteen1/gym`），名单里的 id 必须真实存在于 `campus-geo.json`。

`js/map3d.js`（3.8 万字节）

- `:348`：`compact = W < 420 && Hh < 300`。
- `:575`：`pad` 是标签安全区，现在一律 `{l:0, r:0, t:0, b:8}`。**别再给顶部留位置**：控件已经从画布搬到画布上方的 `.map-modes` 工具栏，留 78 像素会把北侧楼名顶出画框。
- 标签不再有「窄屏白名单」：挤不挤交给 `place()` 逐格碰撞，上限 `namedShown >= 12`（`:504`）。

`page.html`（排版）

- 宽屏（≥1100）两栏：`main` 是网格，左列概览 + 待办列表，右栏地图 + 今天几趟（看 `main` 的 `grid-template-columns` 与 `.trip-stage` 的 `grid-column`）。
- 窄屏（≤720）单栏按顺序排：轮转待办卡 → 今天几趟（`order:2`）→ 待办板（`order:3`）→ 概览（`order:4`）→ 对话（`order:5`）。
- 待办板列表形态规则在 `:2098-2172`；切到别的页签时 `body[data-tab]:not([data-tab=tasks]) .task-board-block{display:none}`。

| 行为 | 用例（`tests/test_ui_browser.py`） |
