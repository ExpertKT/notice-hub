# 群务台 · 演示视频配音稿（4 分 58 秒版）

对应 `演示视频分镜.md` 的八段，一镜一镜照念。全稿约 900 字，正常语速 3.6 字/秒 ≈ 4 分 10 秒口播，留 48 秒给操作停顿，成片落在 4:50–4:58，仍在附件1 要求的 3—5 分钟内。

念法三条：**一、只念屏幕上正在发生的事**，屏幕没动的别说；**二、数字念页面上的**，别念记忆里的（形态效果图那几个数是设计稿，念了就成假数）；**三、标了「可删」的句子超时再删**，其余一句都别省，尤其失败那三段。

## 0:00–0:20 开场

画面：十几个 QQ 群的消息列表快速上滑 → 相册里一堆通知截图 → 备忘录。

> 通知散在群里，截图躺在相册，临出门才想起来翻。上周就这样：三件事办了两件，驿站八点关门，第三件白跑一趟。

字卡已压屏：`群务台 —— 把散在群里的通知，排成今天走得完的几趟`。

## 0:20–0:50 打开就是答案

画面：双击 `启动演示.cmd` → 浏览器自动打开 → 镜头停「今天几趟」抬头，鼠标沿左图两条线慢慢划到右栏两张卡。

> 群务台不问你要干什么。打开就是今天怎么走：五件事，两趟，走路十六分钟。左边地图，右边每站都写着为什么排在这个位置——这节课下课就在这栋楼里，顺路先办。
>
> 武进楼那份实验报告截止在明天，所以落在「排不进去」这一栏，不是漏了。

## 0:50–1:40 说话提一件事（核心镜头）

画面：输入条打「周四下午三点去武进楼 B203 交物理实验报告」→ 回车 → 地图收成窄带 → 停在回复下的「它做了什么」，mouse 停在每条 trace 上。

> 我说一句：周四下午三点，去武进楼 B203 交物理实验报告。回车。
>
> 它先读——五件待办、今天三节课、最后一节三点四十下课；再想这一步该做什么；然后调工具：新建，标题「交物理实验报告」，截止十一月十九号下午三点。
>
> 读、想、调，整个过程就摊在「它做了什么」里，一步不少。

画面：回到常态，待办池多一条、地图多一个点、行程自己重排。

> 待办多一条，地图多一个点，行程自己重排。

## 1:40–2:20 查与改

画面 A：输入「我今天还有哪些事没办」→ 回车 → 回复列出三件，trace 只有一步「读」。
画面 B：输入「把取生活用品那件事改到明天」→ 回车 → trace 出现「改期（第几件 5，截止 11 月 19 日 15:00）」。

> 问它：我今天还有哪些事没办。它读一遍，列出来。
>
> 再说：把取生活用品那件事改到明天。它认到那一件，调改期，参数里写的是人话，明天下午三点。
>
> 增、查、改走同一个入口。模型只管听懂，排序、校验、写库是程序自己的活。

## 2:20–3:00 手机端

画面：竖屏拍摄手机——浏览器菜单「添加到主屏幕」→ 从桌面图标进（全屏、无地址栏）→ 说「帮我记一件：去立行楼交班会材料」→ 回复与过程照常。
弱网这一段拍「等」，不拍「断网」：电脑上把浏览器节流成 Slow 3G，手机再发一句，把等待和回来后的回复都留在画面里。

> 手机上是同一个界面，加到主屏幕，进去没有地址栏。
>
> 说一句：帮我记一件，去立行楼交班会材料。回复和过程一样都在。网络慢的时候它先等着，回来了再更新。
>
> 数据全在电脑上，手机只是个门。

## 3:00–3:43 地图这套不是写死的

画面：设置 →「校园地图」→ 把「图书馆」改名 → 把「快递自提点」摆到地图上 → 删掉一条自己加的临时点 → 三档底图的 key 输入框与「底图状态」汇总 → 回首页：下拉选一次「图书馆」，图上冒出「我」的图钉，把图钉拖到博雅居，松手后第一趟重算。

> 楼叫什么、在哪儿、底下垫谁家的图，都是设置里的事。
>
> 内置的楼只给藏不给删——删了下次你说去图书馆，它分不清是哪个馆。自己加的点随便删。
>
> 底图三档：高德、百度、OpenStreetMap。填谁家的 key 就切到谁家，key 留在本机，不上传。
>
> 起点不用敲坐标，选一栋楼把图钉拖过去就行。
>
> 这套地图接口是公开的：别人学校的底图写成一个小的适配器注册进来，底图按钮上就多一档。

## 3:43–4:23 失败场景（评分里专门有这一项，不许剪）

画面 A：把模型钥匙挪开，说「明天去东门取生活用品」→ trace 自报没有模型 → 再问「今天怎么安排」，照样 2 趟 5 站 1044 米。
画面 B：说「去西门的打印店取材料」→ 建单成功，落进「没说地点」。
画面 C：说一件截止半小时后、又在远处的 → 行程明说塞不下，给两个替代。

> 坏了怎么办，也说清楚。
>
> 模型连不上：它自己会讲「这句按本地规则办的」。再问今天怎么安排，照样两趟、五站、一千零四十四米，楼序不变。
>
> 地点认不出：去西门的打印店取材料——单建了，但列在「没说地点」，不硬塞进行程。补地点也是一句话：这件在图书馆，它就标上，下一趟自己排进去。认不出的楼名它一个字都不写。
>
> 装不下也明说：塞不进的那件，给「明天上午」和「提前出发」两个选择。

## 4:23–4:58 收尾

画面：设置里贴课表 → 行程立刻重排；点「选课表截图」选一张教务截图 → 每节课抄进框里 → 核对后保存 → 行程再变。

> 课表贴进来，行程立刻按新课表重排；选一张教务截图，它把每节课抄进框里，核对之后才保存。
>
> 数据都在本机一个 SQLite 文件和几个 JSON 里。换一片校区放一份地点表，换底图按注册表接一家，两样都不用改代码。模型是可选的：云端一句三到五秒，不想联网就换本机跑的量化模型。

## 录前 15 分钟清单

1. 解压新的 `群务台-演示包.zip`，把云端钥匙写成包根目录的 `llm.key`，双击 `启动演示.cmd`，等窗口打出「模型：云端接口」；随便说一句，两三秒内有真回答才开始录。对话里自报「没有模型」就是钥匙没放好，换一把，别对着本地兜底硬录。
2. 浏览器窗口 1280×800、缩放 100%，关掉系统通知和微信/QQ 弹窗，录屏只录窗口。
3. 手机把演示地址加到主屏幕，提前装好；录的时候直接点图标。
4. 每段先空转两秒再开口，留剪辑余量；鼠标动线慢，别在 3D 地图上乱甩。

## 不许念、不许演的

- 别念形态效果图里的数（2 趟 10.3 分钟那套是设计稿，实跑是 5 件 2 趟 16 分钟）。
- 别说「离线也能改」：断网能开页面、能看到上次排法，但写入一定失败。
- 别说有 APK：手机上能当场演的是 PWA；安卓工程只在开发者工具里验过。
- 别让画面里出现 8766 那份正在用的实例、真实 QQ 号群号、token 明文。

## 评委听到的五个词（口播已经埋好，别改词）

拆解（读 → 想 → 调三行）、工具选择（它自己挑 create / reschedule / day_plan）、执行顺序（先读再改，改完再用工具结果报数）、结果校验（反问确认、塞不下明说）、失败恢复（模型连不上照样排、地点认不出单列）。
