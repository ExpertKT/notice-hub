# 答辩口径卡

用法：评委问哪句，翻到哪条，先给一句话答案，再把证据递过去。证据都能当场打开，别背数字。

口径基准：`F:\nh-agent` 分支 `agent/unified-shell` 的代码（2026-11-19 核对）。行号会随代码动，所以凡是给行号的句子都能按函数名、选择器或接口路径直接搜到——行号对不上就按名字找，名字一直没变。

## 1. 这跟普通的通知聚合 App 差在哪？

别人停在「把通知收进一个列表」，我们往下走一步：算出今天要走几趟、哪站先办，每站还给一句为什么是这个顺序。

证据：`GET /api/agent/plan` 的 `counts` 是 2 趟、5 站、1044 米；页面抬头走路写 16 分钟，因为 `js/trip.js` 把两趟的分钟相加（9 加 7，按总里程折算 14.9）。行程说明里有「起点用最后一节课的立德楼，不用先回宿舍」（`application/trips.py`）。

## 2. 「智能体」是真在决策，还是关键词 if-else？

模型只决定调哪个工具、带什么参数、怎么把结果说成人话；站序、分钟数、每站理由都是规则算的，能复算、能对账。关键词匹配不出「先 `poi_near` 再 `plan_route` 比顺序」这种两步。

证据：入口 `agent_chat.chat_turn`（`application/agent_chat.py`），可用地点清单也在这个函数里拼进提示词；站序在 `application/trips.py` 的 `_order_stops`（最近邻那行是 `nxt = min(remaining, key=lambda item: _distance(cursor, item["place"]))`，起点为空时直接取第一个）；分钟在 `application/route_tools.py` 里两处都除 `WALK_M_PER_MIN`；每站理由在 `trips.py` 的 `_why`。

## 3. 模型具体负责到哪一步，哪些是你们自己写的？

模型管三件：听懂那句话、挑工具和参数、把执行结果说成人话。剩下全是我们写的代码。

证据：`POST /api/agent/chat` 的 `trace` 三段——读、想、调，渲染在 `web_static/page.html` 的 `agentTrace()`（按 `step.kind` 分标签），默认摊开不用点（`aria-expanded='true'`、`list.hidden=false`）。改事闭环：发「把『去博雅居拿快递』挪到明天下午两点」，HTTP 200、`changed=true`、trace 里 `tool=reschedule`、`ok=True`、`detail=已改期`，`say` 是「已改好，『去博雅居拿快递』截止时间改到明天下午两点。」；落库在 `week` 桶、`deadline=2026-11-19T14:00:00`，当天 `/api/agent/plan` 里就没有博雅居了。

## 4. 排程为什么这么排，凭什么说顺路？

先按片区把手上的事分组，组内最近邻一站接一站，塞不进空档的单列。步速只有一个来源，70 米/分钟，注释写着含进楼、找教室、等电梯。

证据：`application/trips.py` 顶部 `WALK_M_PER_MIN = 70.0`；分组在 `_build_trip`（按 `zone` 归档）；最近邻在 `_order_stops`；手排优先的入口也在 `trips.py`——固定的先放，其余再交给 `_order_stops`；路线工具 `application/route_tools.py` 导入这个常量、两处都除它、`basis` 也念它。给模型的提示词也读同一个常量（f-string）——以前那里写死 75，模型嘴里和面板会对不上，`890dd41` 改掉了，`tests/test_application_agent_chat.py` 的 `test_prompt_quotes_the_same_walking_speed_as_the_tools` 锁着。**三处一个数：70。**

演示真值：2 趟、5 站、1044 米、走路 16 分钟。第 1 趟 15:40 立德楼→立行楼→图书馆，586 米、9 分钟；第 2 趟 16:30 第一餐厅→1 号楼，458 米、7 分钟。把还书挪到明天之后：4 站、762 米、走路 12 分钟。

## 5. 换一个学校能用吗？

改数据，不改代码。

证据：楼名、别名、片区在 `application/campus.py` 的内置楼表里（27 条，含武进楼）；坐标在 `web_static/js/campus-geo.json`（`campus.py` 的 `GEO_FILE` 指向它、`load_pois` 读入）；数据目录里放一份 `campus_poi.json`，同 id 覆盖内置那条，写坏了当没写。

## 6. 手机端凭什么算做完？

390 宽重排成一列，底栏 72px 加安全区，行程里的站只留楼名，概览不再给行程让位（限 40vh、内部滚动）。本机 `127.0.0.1` 或 https 下有「装到桌面」，`web_static/js/pwa.js` 判 `isSecureContext` 与是否已安装。

边界照实说：安卓走局域网 http 只能往桌面加个快捷方式，浏览器不给装桌面的入口；仓库里有安卓工程（`android/`，22 个文件），没打过包、真机没验过，全仓一个 `.apk` 都没有——别答「有 APK 能装」。

## 7. 断网了怎么办？

分两种地址，答案不一样：

- 本机 `127.0.0.1` 或 https：service worker 装得上，断网重开能出页面，页里标着「上次的排法 · 时间」（`js/trip.js`），底部一条通栏「没网了。这一页是上次打开时留下的，连上以后点「重试」才更新。」，整页只读、写不进去。
- 局域网 `http://电脑IP:端口`：浏览器不给 service worker（实测 `isSecureContext: false`），电脑一关手机就打不开。

数据请求一律失败，`/api/` 故意不缓存——旧数据装成新数据比打不开更糟。被问「地铁上能用吗」，答不能，要等到有网。

证据：`web_static/js/sw.js` 的 `SHELL` 只列外壳（首页、manifest、4 个图标、11 个脚本），并跳过 `/api/` 与非 GET；注册在 `page.html` 里 `nhSecureShell` 守卫之后（`navigator.serviceWorker.register('/js/sw.js', …)`，只在 https 与本机地址）；浮条 `#net-bar` 固定在底部，那句文案也在 `page.html` 里。

## 8. 哪些地方写死、写死在哪？

真决策只有一层：`agent_chat.chat_turn`（`agent_chat.py`）让模型决定调哪个工具与回复正文，可用地点清单也在那里拼进提示词。其余写死，逐条可核：

- 站序 `trips.py` 的 `_order_stops`：`nxt = min(remaining, key=lambda item: _distance(cursor, item["place"]))`，起点为空时直接取第一个。
- 分组 `trips.py` 的 `_build_trip`：`zones.setdefault(str(stop["place"].get("zone") or "未分区"), []).append(stop)`。
- 手排优先也在 `trips.py`：固定的先放，剩下交给 `_order_stops`。
- 每站理由 `trips.py` 的 `_why`，五条固定文案：从这里出发、第一站没课表、就在下课的这栋楼、同一栋楼还有一件、接着走 N 米比再跑一趟省一次往返。
- 分钟 `route_tools.py` 两处都除 `WALK_M_PER_MIN`（70，`trips.py` 顶部）。
- 地点与片区 `campus.py` 的内置楼表，坐标另在 `campus-geo.json`。

## 9. 跟微信、钉钉的日程比，价值在哪？

它们替你记，我们把你记下的几件事排成一条走得完的线，每站带到点时间、米数，还有一句为什么先办这件。

证据：plan 每站带 `arrive`、米数和 `why`；`trips.py` 的 `_why` 只写算出来的事实，不编理由。

## 12. 演示包要不要联网？没有模型钥匙怎么办？

要联网，模型走云端接口。包里不带钥匙——`提交清单.md` 那两条写的就是「无 `llm.key`、无 `.env`、无 `data/`、无 `logs/`」和「这个包不带任何钥匙」。要真对话，自己把一把 key 写进解压后 `启动演示.cmd` 同目录。

没钥匙时对话按本地规则办，不是只会说读不懂：交代一件事真提一条待办，问还有几件没办报件数，问「今天怎么安排」真排一遍（2 趟、5 站、1044 米、头一趟 15:40 从立德楼起走立行楼、图书馆），问「立德楼附近有什么」报 15 处地点、5 件未完，再列由近到远三处米数。只有模型才懂的那类话，它直说「这句我按本地规则读不懂」。

证据：本地规则全在 `agent_chat._no_model_turn`（`application/agent_chat.py`），提事落库走 `_local_fallback`；两句自报是 `_RULE_STEP` 与 `_RULE_DUNNO`，读不懂时就回后者。

## 13. 有多少人在用？数字哪来的？

GitHub 仓库 104 star、9 fork；现存 20 个 Release（v1.0.0 → v1.1.0，含 beta.1/2/4–19）附件累计下载 **1639 次**，拆开是电脑版 zip 1232、手机 APK 407；正式版 492、测试版 1147。单版最高 beta.2 460 次、v1.0.0 454 次、beta.12 200 次、beta.14 124 次。近两周（11-04 → 11-17）仓库浏览 988 次、独立 348，克隆 1192 次、独立 327。抖音两条演示视频播放 21.9 万、收藏 5284（1830 + 3454）。Gitee 镜像同步 17 个版本，接口和渲染后的页面都不给下载次数。

1639 只算现存版本：另有 20 个日期版（`v2026.10.8`–`v2026.10.27`）当初发过 Release，本地 `.reports/task-release.md` 与 16 份 `release-notes-v2026.10.9` 起的发版说明还在，如今按 tag 查全 404，那批计数跟着 Release 一起没了，所以真实累计比 1639 高。

取数：`gh api repos/ExpertKT/notice-hub/releases --paginate` 拉全量，逐版本把附件 `download_count` 相加；流量走 `gh api repos/ExpertKT/notice-hub/traffic/views` 与 `/traffic/clones`（GitHub 只留 14 天）；Gitee 走 `https://gitee.com/api/v5/repos/ExpertKT/notice-hub-mirror/releases`（附件对象只有 `name` 和 `browser_download_url`）。抖音那两条是作者后台的数。逐条对账底表在桌面交付夹的 `对账底表-下载数.csv`（50 行，含 20 个日期版标 NO）。

被追问就照实划三条边：下载不等于在用；抖音的播放是「看见」，收藏才是「想留着用」；没埋点，所以没有留存率、日活这类数。

## 14. 地图上那条线怎么画的？有一段看着就是直线。

分两步：先按直线距离定顺序（八点以内枚举全排列，再多走最近邻加 2-opt，都是直线距离——只为了排顺序，40320 次评估不能每次都跑一遍寻路），再对每一段在路网快照上求折线，绕楼、避水，绕不通就退回直线。

证据：`application/campus_roads.py` 的 `road_line()` 每段先试路网图（绕行不超过直线 1.9 倍才用），不行退格子 A*（12 像素一格，楼块水面当障碍），再不行就那一段原样直线；`application/agent_plan.py` 的 `_attach_road_lines` 把整趟折线挂到 `trip["line"]` 上给地图画。

那一段确实就是直线，而且页面会自己说出来：每段带 `road = {path, degraded, reason}`（`campus_roads.py` 的 `road_leg()`），`degraded` 只在这一段只画得出两点、而那条直线中间压着楼或水面时才为真（`reason="straight"`），页面标「这一段没接上路网，按直线估的距离」。两栋楼挨着、直线本来就走得通的是 `routed`，不标——乱标等于把好路说成坏路。校区 27 处地点两两配对 351 对里有 73 对凑不出合法折线（直线本身压着楼或水面），这些段就按直线画并标明，不假装是路网。

数字（实测）：相邻楼之间绕行 1.2–2.1 倍直线，立德楼→立功楼 1.21 倍；立德楼→立行楼中间压着一栋楼，最短合法路线是 2.05 倍（合法、不穿楼，`tests/test_campus_roads.py` 的 `test_a_building_in_the_way_costs_distance_not_legality` 锁的就是「贵但合法」）；演示那趟博雅居→立功楼→图文信息中心楼画出 38 个点、1.85 倍、14 毫秒。题头写的是「绕楼」不是「沿路」：快照只有外圈和几条干道，楼与楼之间一条人行道都没有，写「沿路」是骗人。

## 现场别说的三句

- 「完全离线可用」——局域网 http 下没有 service worker；本机或 https 下也只是外壳加只读快照。
- 「AI 全自动」——站序、分钟、每站理由都是规则算的，模型只挑工具。
- 「零配置换校区」——楼表、坐标表、片区常量都得对一遍。

## 不够硬的几条

1. 第 10 条：另一位队友的姓名学号还没给，写「待填」，别替人编。
2. 第 6 条：安卓 http 下只能加快捷方式，评委追「算不算装到手机上」，答不算；`android/` 有工程、没打包、真机没验过，别说有可装的 APK。
3. 第 7 条：目前要电脑开着、走本机或同一局域网；断网只剩只读快照。
4. 小程序：仓库有 `miniprogram/` 源码工程，只在开发者工具里验过，真机要换自己的 AppID 与 HTTPS 合法域名，别说成「有小程序能跑」。
5. `提交清单.md` 里那五项包数字（字节数、sha256 前 16 位、文件数、源码提交）等重出包后一次改准，现在别引用。
