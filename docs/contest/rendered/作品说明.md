# 群务台 · 作品说明

> 一句话：群消息里的通知变成待办，待办再排成今天几趟路。

关键词：通知聚合 · 智能体调度 · 路径安排规划 · 便携式。

参赛赛道：二（工具调度与自主任务智能体）。同目录另有《群务台项目计划书.pdf》《操作说明.md》《演示脚本.md》《演示要点.md》。

## 一、解决谁的问题

常州大学西太湖校区，班群、助教群、社团群一天几十条消息。实验报告周五 23:59 截止，这句话埋在某条四百字通知中间；交班会材料要送到立行楼 302；还书得跑图书馆；生活用品在学生公寓 A。这些事分散在教学楼、图书馆、食堂和宿舍之间，单程都在十分钟上下，而一个下午只剩课与课之间那一百来分钟。

现有工具各管一段：群消息靠人往上翻，待办清单只回答「有什么」，地图只认地名、不认「这件事在哪办、几点关」。学生自己心里的算法是：拿最后一节课下课的楼当起点，把顺路的几件串成一趟。群务台把这套算法写成了程序。

## 二、它是什么

三条数据流，各自独立：

1. **收**。NapCat 把 QQ 群消息 POST 到 8765，receiver 落库、按白名单过滤，service 攒批交给 summarizer，产出标题、截止时间、置信度，拿不准的进「候选」等用户确认。推送走 QQ 机器人、WxPusher、Server 酱、PushPlus 或 Webhook。
2. **看**。待办台按今天 / 本周 / 以后 / 已完成分组，可导出 .ics 给系统日历，数据落在安装目录的 SQLite 里。
3. **排**。这一版新加的一层：`/api/agent/plan` 把课表、待办、常做的事、校区地点合成「今天几趟」。

排程坏了不影响收消息，模型连不上不影响排程。这条边界是刻意划的。

## 三、智能体的决策链

用户说一句「周四下午交实验报告、还书，顺路吃饭」，后端会走完一条完整的链（`noticehub/application/agent_chat.py` 的 `chat_turn()`）。

**读**。先把上下文摆到模型面前，同时落一条 trace：「读了 5 件待办、今天还有 3 节课（最后一节 15:40 下课），和刚才 0 轮对话」；课上完了就换成「读了 5 件待办、今天的课都上完了」。课表读不到就少这一句，不拖垮对话。

**想**。模型只被允许回一个 JSON：`{"say": "...", "calls": [...]}`，系统提示里写明工具名只能取十个之一：`act / create / rename / pin / urgent / reschedule / clear_finished` 管待办，`plan_route / poi_near / day_plan` 管路线与行程。模型要说的话写进 say，这条进 trace 的「想」。

**调**。每轮最多取 3 个调用，同一个调用键去重，总共两轮。每个调用执行完记一条 `{"kind": "call", "tool", "args", "ok", "detail"}`，页面上渲染成「改期（第几件 2，截止 11 月 19 日 15:00）：」后面接工具返回的那句话。参数也翻成中文，不会把 `2026-11-19T15:00` 的原文甩在屏幕上。

**回流**。执行结果拼回下一轮对话，模型据此决定还要不要动手。两轮用完就收，不无限循环。

页面上这块叫「它做了什么」，默认摊开。原因写在代码注释里：折叠起来只剩一行标题，等于把过程藏了。

### 一次自己挑工具：先看附近，再定顺序

输入：「立德楼这边下课，把还书、交班会材料、交实验报告排一下，先看附近还有哪些没办。」

第一轮它选 `poi_near`（place=立德楼，radius_m=500）。工具返回立德楼 500 米直线半径内 15 处地点，由近到远：立德楼 0 米、立行楼 155.1 米、武进楼 270.9 米、汤湖楼 293.1 米、第一餐厅 293.7 米……图书馆排第七，295.5 米。这些地点上的未完待办一并列出来。

第二轮它换 `plan_route`（points=图书馆、立行楼、武进楼，start=立德楼）。返回：立德楼 → 立行楼 → 武进楼 → 图书馆，三段 155.1、413.6、43.1 米，合计 611.8 米、步行 8.74 分钟；按输入顺序要走 1139.8 米，省 528.0 米。8 个点以内枚举全部访问顺序求开放路线的最短解，`algorithm` 写 `exact`；超过 8 个点退回最近邻加 2-opt，且保证不比输入顺序更长。

这组数不是模型写的。两个工具都返回 `changed: false`，只能算、不能改待办；页面上「调」那一行直接印工具返回的 detail，模型要报里程只有这一个来源。限制也写在返回里：`plan_route` 的 `basis` 是「校园米制坐标直线估算，步速 70 米/分钟；未计道路、进楼、办理时间及营业时间」，`poi_near` 另注一句「附近待办未校验截止时间、营业时间和沿途绕行距离」。两处都用 70 米/分钟，和「今天几趟」同一套步速，区别是那边还要加每站 10 分钟办事和截止校验。

在源码包根目录可以复现第二段：

```
.venv\Scripts\python.exe -X utf8 -c "import json; from noticehub.application.route_tools import plan_route; print(json.dumps(plan_route(['图书馆','立行楼','武进楼'], start='立德楼'), ensure_ascii=False))"
```

### 失败与越界怎么处理

护栏写在代码里，不靠提示词祈祷：

- 白名单之外的工具名，执行不了。
- 删除和清空要二次确认：第一次只记 pending，用户回「确认」才真动手。
- 还在进行、又不是手动建的任务，只许「忽略」，不许删。
- 说「第 3 件」但对应不上，或者标题对上好几件，就把候选列出来让用户说全，不猜。
- 模型没产生任何动作、而用户话里带动作词（「删掉」「改到」），补一轮重试。
- 模型超时按人话报：「模型太慢，这一轮没等到回应」。云端单次调用 25 秒上限，本机模型 90 秒硬顶。
- 会话存在进程内存里，重启就丢。这是限制，写在第八节。

## 四、排程：这一层刻意不碰模型

`noticehub/application/trips.py` 开头写着：地点识别有规则兜底，聚类、排序、步行时间、截止校验全是本地计算，所以模型连不上时行程依旧排得出来。

输入是今天的课表、带地点和截止的待办、常做的事（比如「第一餐厅 吃饭 30 分钟」）。算法：

- 用课表挖空档，短于 25 分钟不算一趟；
- 起点取今天最后一节课所在的楼，不用先回宿舍；
- 同一片区的点先聚，区内按最近邻排；
- 步行按 70 米/分钟折算，含进楼、找教室、等电梯，每站留 10 分钟办事；
- 塞不下或会错过截止的进 overflow，写「这一趟塞不下，建议明天上午或提前出发」；
- 办事窗口会关的，给一句「XX 的办事窗口到 17:30 就关，这趟可能会白跑」。

每一站都带一句「为什么是这个顺序」，只写算出来的事实：「就在下课的这栋楼里，顺路先办」「接着走 158 米，比再跑一趟省一次往返」。页面另给一段核对句：「起点用最后一节课的立德楼，不用先回宿舍」「这一趟 3 件、走路 9 分钟，15:40 出发」。用户不必信，自己核。

算出来的顺序不是终稿。用户可以把「常做的事」直接拖进行程里、也可以拖着某一站换位置；松手后这份站序会发给服务端存下来（`action=order`，落数据目录的 `campus_plan_order.json`，留最近 14 天），刷新、第二天再来都还在。存不上时不回滚页面上的顺序——用户刚摆好，回滚等于「什么都没发生」——改成明说「顺序没存上，刷新会回到按远近排的走法」。小组内手排优先于最近邻，跨区仍然按片区成趟，不会为了顺序把行程拆散。

拿演示数据算（`demo/seed.py` 的 seed，按 OSM 换算后的 27 处地点重算）：5 站、2 趟、1044 米，两趟走路合计 16 分钟（每趟分段取整，所以比按总里程折算多一分钟）。第 1 趟教学区 15:40 出发，586 米、3 站：15:40 立德楼 512 找同学拿材料，15:53 立行楼 302 交班会材料，16:10 图书馆还书；第 2 趟生活区 16:30 出发，458 米、2 站：16:30 第一餐厅吃饭，17:03 1 号楼取生活用品。武进楼 B203 那份实验报告截止在明天 18:00，今天排不进去，单列在「排不进去」里并写明理由「安排在 2026-11-19，不排入今天的行程」——不是漏了，是算法知道今天赶不上。27 处地点全部认出。两张行程卡上的分钟各自取整（9 加 7），抬头把两趟相加写 16，所以比按总里程折算多出一分钟。这份数据可复现，`demo/启动演示.cmd` 的 seed 就是它。

## 五、地图

校区画在米制平面上：原点在校区西北角，x 向东、y 向南，一格 0.9 米；楼位、轮廓和路网从 OpenStreetMap 数据换算过来（`noticehub/web_static/js/campus-geo.json` 存坐标表，`js/campus-osm.js` 存路网快照）。不用经纬度，因为这套计算只关心相对距离。地点存在数据目录的 `campus_poi.json` 里，每条带别名、片区、坐标、类型和营业窗口。加载时先铺一份内置的，再用文件里的同 id 条目盖上去；写一个新的 id 就多一个地点，不用改程序。文件写坏或某条缺坐标，那条当不存在，照旧用内置的——排程不该因为一份 JSON 写错就崩。换学校，换的也是这份文件。

页面上是真 3D：每栋楼按轮廓挤成体块，打一盏光、落下影子，能拖着转视角；没有 WebGL 时退回 SVG 平面图。两种画法共用一份数据，坐标来自 `/api/agent/plan`，页面不自己编数字。

## 六、手机端

手机是第一现场，所以窄屏重排、概览不让位、装到桌面、断网说清楚这四件都做了。

**390 宽重排**。网页在窄屏上不是把桌面版缩小：底栏 72px 加安全区；行程里的站只留楼名，时间挤进去就读不出顺序；地图单指竖滑滚页面，横向拖动转视角；待办概览压成一句话「今天 2 趟 · 最近 20:00 · 完成 0/5」，右边一个「展开」；底栏五个常去的地方（待办 / 详情 / 最近推送 / 收件箱 / 设置），顶栏一键切回桌面版。`?phone=1` 可以直进手机模式，退出时地址栏参数会自己清掉。

**有行程时概览不让位**。以前那一版是 `body.has-trip .summary{display:none}`，手机上带着行程进首页只剩「今天几趟」，五件待办一件也看不到。现在概览留着，限高 40vh 并在内部滚动（`noticehub/web_static/page.html:1953`），待机输入栏随滚动停在底部，两者互不顶掉。

**待办详情**。卡片下面多了一块「待办详情」，长内容在里面单独滚动、收起后列表位置不动（`page.html:3740`）。点「拿这件事问智能体」（`page.html:3743`）一次就把标题和原话带进对话，回复上方标明关联的是哪件待办，失败重试也带着这些内容。

**点别处就收回对话**。对话框抬头后地图只剩一条扁带，人去看别的事时它该自己回来——点页面别处就把对话收回成那条扁带（`page.html:6054-6059`），不用再去找右上角的「收起」；Esc 也还在。

**可安装**。`manifest.webmanifest` 里 display 是 standalone，方向锁竖屏，图标有 192、512 和 maskable 版本，iOS 另带 `apple-touch-icon`。走 https、或者在本机 `127.0.0.1` 打开时，页头右边出现「装到桌面」（装过就不再出现），点开是「在 Safari 底部点「分享」，再选「添加到主屏幕」」。装完点图标进去没有地址栏。这个按钮只在安全上下文里出现（`noticehub/web_static/js/pwa.js:22` 判 `isSecureContext`）；手机用局域网 http 地址打开时它不出现，只能手动从分享菜单加。安卓那边仓库里只有工程（`android/`，22 个文件），没打过包、真机没验过，全仓一个 `.apk` 都没有；要装得自己构建，步骤写在 `操作说明.md`。构建出来的那个外壳扫码配对、6 位数字码兜底，连的还是电脑上这份服务，数据留在电脑上。

**断网**。service worker 只缓存外壳（manifest、图标、首页、十一个脚本）、`/api/` 一律不缓存，所以断网能打开页面、看到上次的排法（页里标着「上次的排法 · 时间」），看不到新数据——把旧数据当新数据显示，比打不开更坏。它只在本机 `127.0.0.1` 或 https 下才注册（`page.html:3262-3271`），手机用 `http://电脑IP:端口` 打开时浏览器不给 service worker（实测 `isSecureContext: false`），关掉电脑那台手机就打不开，不是「离线能用」。断网时页面不留假象：底部挂一条通栏，没网写「没网了。这一页是上次打开时留下的，连上以后点「重试」才更新。」，本机服务没开写「连不上群务台的服务。它可能被关掉了：双击 QQ-Notice-Hub.exe，再回来点「重试」。」，两句后面都接「当前只读；保存、改待办和对话暂不可用」，同时把发送、语音、保存课表这些要写数据的按钮置灰。

**微信小程序**。`miniprogram/` 是同一条数据流的第二个入口：待办、对话、地图、设置四页，tabBar 三个 tab，深色主题跟着系统的 `darkmode` 走（`theme.json` 一套变量），触控尺寸 88rpx，空态、骨架屏、长文本截断都做了；地图用的是和网页同一份 27 处校区地点（`assets/campus.js` 由 `DEFAULT_POIS` 生成，名字与别名按长度倒序匹配，「11 号楼」不会抢走「1 号楼」）。静态检查 `checks/check.cjs` 跑 `node` 一把过（页面与配置、HTTP 失败分类、对话成功/降级/取消、看板解析、地点别名优先级、地图选中与标签抽稀、深色逐页）。它连的是本机服务，所以在开发者工具里演示；真机要服务所在电脑在同一个局域网。

## 七、装起来试

Windows 10/11 加 Python 3.12 以上，双击 `demo/启动演示.cmd`。它在 8899 端口起一份独立实例，数据在 `demo/data`，不碰装在 8766 的那份。脚本先写 5 件待办、3 节课、1 条常做的事，再打开 `http://127.0.0.1:8899/?token=demo&demo=1&nowiz=1`。模型按启动器同目录的 `llm.key` 选：源码版放在 `demo\llm.key`，安装版放在包根目录。写了钥匙就走云端 OpenAI 兼容接口，没写时后端设为 `auto`，对话按本地规则办并自报「没有模型，这句按本地规则办的」，排程照常。

## 八、已知限制

1. 楼位与道路据 OpenStreetMap 数据换算，个别楼是估算位置（图上用虚线标），不是测绘数据。步行按 70 米/分钟折算，跟真实走法有出入。
2. 区内排序用最近邻，不是最优解，点多时会明显绕。
3. 课表截图识别后先给草稿，要人核对再存，不直接落库。
4. 会话在进程内存里，重启服务，对话就断。
5. 单人单机：没做多用户、权限和云同步。
6. 断网时能剩多少要看打开方式：本机 `127.0.0.1` 或 https 下有 service worker，外壳能打开，页里标着「上次的排法 · 时间」，底部浮一条「没网了」，这时只读、写不进去；手机走局域网 http 时浏览器不给 service worker，连外壳都打不开。数据请求一律失败，`/api/` 不缓存是故意的。
7. 小程序要连本机服务，只在开发者工具里验过；真机演示得让服务所在电脑和手机在同一局域网，深色主题也没在真机上逐页核过。

## 九、来源标注

- **OpenStreetMap**：楼位、校区轮廓和路网来自 OpenStreetMap，落盘为 `noticehub/web_static/js/campus-geo.json`（坐标表）和 `js/campus-osm.js`（路网快照），属派生数据；署名 © OpenStreetMap contributors、ODbL 1.0，显示在地图右下角。OSM 上没有楼面或没有名字的几处，用校方平面图拟合换算（约 ±20 米），图上画成虚线。
- **Leaflet 1.9.4**：只有切到在线 OSM 底图时从 unpkg 载入（`js/trip.js:979-984`），BSD-2-Clause。默认的自绘底图不联网、不依赖 key；在线档另可选高德、百度，要各自的 key，署名同样在右下角。
- **three.js**（`noticehub/web_static/js/three.module.min.js`，版权行 Copyright 2010-2023 Three.js Authors），随仓库分发，用于 3D 校区渲染。
- **PyInstaller**：打包成 exe 用的工具（`packaging/noticehub.spec`、`packaging/launcher.spec`），GPL 2.0 加例外条款，只用于构建，不进产品运行时代码。
- **NapCat / OneBot v11**：QQ 协议侧，独立资料目录，群务台只走 8765 的 HTTP 上报。
- **模型**：云端 `deepseek-flash`（五句实测：三句 2.4~3.2 秒，多调一轮工具那句 11.9 秒，平均 4.6 秒；本机 Ollama 的 `qwen3.6:35b-a3b-q4_k_m-gpu20` 作对照是 14 秒）；端点可换成任意 OpenAI 兼容服务。本机 Ollama 只在手动把 `NOTICEHUB_LLM_BACKEND` 设成 `ollama` 时用。模型只负责把话说成 JSON、挑出通知，排序与校验不走模型。
- 其余为 Python 标准库与仓库自身代码，数据落本地 SQLite。
