一项目概述

1.1 这次做的是什么

群务台原先是一个 QQ 群通知聚合工具：把几十个群里的通知收进一张待办表，别再刷屏找消息。这次改造的重点不在界面，而在「先做什么、什么时候出门」。它现在每天排出一份行程：把待办按楼的位置和课表时间分组，算出今天要走几趟、每趟先去哪后去哪、几点出发、路上花多久，装不下的明说装不下。

用户只需要往池子里放事——群里转发过来的、自己随口说的、截图里的——排的事情交给程序。

1.2 用户与场景

使用者是在校本科生，尤其是班委这类要接事的人。典型的一天：上午满课，中午在食堂刷到两条新通知，下午 15:40 在立德楼结课，之后到晚饭前大概两小时空档。这段时间里他要找同学在立德楼 512 拿材料、把班会材料送到立行楼 302、去武进楼 B203 交物理实验报告、到图书馆还书，回宿舍前还想取一趟生活用品。这些点散在教学区与生活区两头，楼与楼之间步行十分钟起，来回跑三趟会把空档用完。

现在多数人怎么解决：把群消息截图存相册、或者记在手机备忘录里，临出门前翻一遍，凭记忆判断先去哪。结果是当天办掉离得最近的两件，剩下的拖到下周，还有一件因为忘了营业时间白跑一次。

1.3 三个能力

  • 收得进来：QQ 群消息经 OneBot 上报落库，文本里抽出地点和截止，进同一个待办池。没写地点的不硬猜，单独列出来等人补。
  • 排得出来：读课表算今天剩下的整段空档，按楼分组，组内按距离最近邻排序，按截止时间和营业窗口校验。结果是一到三趟，每趟带出发时间和逐站到达时间。
  • 办得掉：出门后每站勾一下销账；没办成的回到池子。对话里说话就能改——加一件、改期、把某件标成已办。

1.4 与同类做法的差别

对比对象它的做法群务台的做法
群消息机器人关键词提醒，把消息再发一遍消息落成带地点和截止的事项，参与排程
待办清单 App按截止或手动排序，不管人在哪以「一趟出门」为单位，距离和时间窗是硬约束
课程表 App只显示课，不接管课后的事课表是排程的边界：只在最后一节课之后安排出门
通用大模型问答问一次答一次，答案不留、不改数据对话只是入口，结果落到行程表和数据库；模型挂了行程照排

创新落在五个动作上，不是加一个聊天框：拆解——一句话拆成工具与参数，不让模型直接动数据库；工具选择——十二件工具划清边界，越界的话术（安装、设置）明确不接；执行顺序——先读今天的待办与课表，再决定改哪一条，参数对不上就反问；结果校验——每一步的参数和结果都回显，改期前先说改成哪天，装不下明说装不下；失败恢复——模型没连上降级并说明、地点认不出单列不硬塞、同一轮重复调用只做一次。

这五个动作不是话术，每一件都能在界面上指出来、在代码里找到落点：

动作具体做了什么演示时屏幕上看到什么代码位置
拆解一句话只许拆成「说一句 + 调哪几件工具 + 参数」，不让模型直接动数据库回复正文下面那一行「想」：这一跳打算做什么；接着是「调」里的工具名和参数application/agent_chat.py 系统提示只接受 JSON；_parse() 把正文拆成 calls
工具选择十二件工具名写死在提示里，越界的话术（装软件、改设置、托管、更新）明确不接；名字对不上就什么都不执行同样是「新建一件事」，说的是「查附近」就出现 poi_near，说的是「今天怎么安排」就出现 day_planagent_chat.py 工具白名单与参数表；_run_call() 在服务端分发，模型只能"要求"，执行在代码里

结果校验对不上唯一一条待办就不调用，先问是哪一条；这一轮没改到待办时，模型说的"已经记下"一律作废，改用工具结果；装不下、营业窗口不够都明说说「把还书改到明天」时先复述改成哪天；行程卡底部写着排程依据；塞不下的那件出现在「今天塞不下」并带替代建议agent_chat.py _resolve() / _should_retry() / 无改动即以工具结果为准；trips.py 关门告警与 overflow
失败恢复模型通道任何失败都不端给用户：换本地规则真落库、真去算；没有钥匙也能查能提；同一轮同样的工具加同样的参数只执行一次模型连不上时页面写「模型这边连不上，我先按看到的记：」，后面照样建单、行程照样重排；地点认不出照样建单，进「没说地点」agent_chat.py _ask() 捕获全部异常 → _local_fallback()；_no_model_turn()；_call_key() 去重

1.5 输入条件与预期输出

项内容
输入条件QQ 群里的通知文本（经协议端上报）、用户口语一句话（提事 / 查事 / 改事）、一份课表、一份校园点位表（楼名、别名、坐标、营业时间）。课表可以贴文字，也可以选一张截图让本机多模态模型读。
预期输出三样东西同时给：①「今天几趟」——每趟的出发时间、逐站顺序与到达时间、走路合计、装不下时的替代建议；②待办表的变化——新建 / 改期 / 完成落在库里，刷新后还在；③「它做了什么」——读了几件待办和几节课、这一跳的判断、每个工具的参数与结果。
不做什么不做导航（不给经纬度、不纠偏车道、不做实时路况）、不替用户决定请假或改课表、不在云端存数据。底图默认自己画，不挂任何厂商的 key；想换成真底图可以在设置里填高德或百度的 key、或者换一个 OSM 瓦片源——那是可选的一层，不填也完整可用，生图与算路都不经过网络。

二技术方案

2.1 总体架构

单进程 Python 程序，本地运行，数据落 SQLite 单文件（digest.sqlite3）。分四层：

层负责什么代表文件
接入层接 QQ 协议端上报、探测与启停、写配置noticehub/adapters/receiver.py、napcat_admin.py
领域层事项模型、状态流转、去重合并、截止推算noticehub/domain/

界面层网页界面、等距校园图、对话卡片web_static/page.html、web_static/js/trip.js

界面是原生 HTML/CSS/JS，没有前端框架，也没有打包步骤；后端用标准库的 HTTP 服务。整个产品不带前端构建链，装完即用。

2.3 模型与工具

模型接 OpenAI 兼容接口：云端只要一把钥匙加三个环境变量（端点、模型名、钥匙），没有钥匙时可切本机 Ollama 跑量化模型，演示版按有没有 demo\llm.key 自己选。产品不使用各家互不兼容的 tool-calling 字段，而是要求模型在正文里回一段 JSON：

{"say": "一句中文", "calls": [{"name": "create", "summary": "…", "deadline": "明天下午"}]}

服务端解析后执行，把执行结果作为一条消息回喂模型，最多两跳。当前开放的工具十二个：会改数据的九个（新建、改标题、改期、改状态、置顶、标紧急、清空已完成、改起点、标「我现在在哪」），只查不改的三个（看今天怎么排、看路线、看附近）。

工具参数作用
createsummary, deadline新建事项，截止没有钟点时按上午 09:00 / 下午 15:00 / 晚上 20:00 兜底
renametask_id, summary改标题
rescheduletask_id, deadline改截止
acttask_id, action完成 / 确认 / 忽略 / 恢复 / 稍后 / 删除
pin / urgenttask_id置顶、标紧急
clear_finished—清空已完成，需再确认一次
day_plan / plan_route / poi_near / here—；points+start；place+radius_m；place只读四件：今天的行程、多点最优顺序、附近还有什么没办、我现在在哪栋楼。都不改待办，失败也不写库

模型轮流失效时的处理：正文不是 JSON 就当闲聊回一句，不动数据；该调用没调用，服务端补一跳，在消息里明说「上一次没调用工具」，让模型改；接口报错不退回页面写死的固定说法（否则同一句话会改两遍），直接把错误原因说给用户。

模型管到哪为止。模型只做两件事：听懂这句话要干什么、从工具表里挑一个并把参数填对。排程、认地点、抠时间窗、校验装不装得下、写库，都是本项目自己的确定性代码，模型挂了也不影响——行程照排、地图照画，只是对话入口降级。这条边界是刻意划的：把判分里要「可核验」的部分放在代码里，把需要理解语言的放在模型里。同一轮里同样的工具加同样的参数只执行一次，模型把上一句话又说一遍时不会重复建单。

2.4 关键技术

地点识别。校园地点表内置 27 个点位，每条带名称、别名、分区、平面坐标和营业时间。匹配时按别名长度倒序，长的先试，免得短别名抢先命中；认不出就返回空，不猜。

时间窗。把今天的课按开始结束时间在白天（08:00–19:00）里挖掉，剩下的整段空档短于 25 分钟就丢弃，因为一次出门只够走一趟。起点取今天最后一节课所在的楼——下课直接走，省掉回宿舍再出发的一次往返。

排序与校验。先按楼的分区把事项分组（同一片区一趟办完），组内用最近邻贪心排顺序，逐站累加步行时间（70 米/分钟，含进楼找教室，比纯步行保守）和停留时间（每站 10 分钟）。任何一站超出当天截止或超出窗口末，就移到「今天塞不下」并给出替代说法；如果某栋楼的关门时间早于离开时间，直接给告警「这趟可能会白跑」。

地图。底图默认自己画，不挂厂商 key：等距投影 iso(x,y)=((x-y)·cos30,(x+y)/2)，楼按 x+y 升序做画家排序，画顶面和两个侧面。路线画在楼之上——挡住就看不出「顺路」这件事。楼名先到先占位，后来的名字跳过，窄屏只标行程里那几栋，编号最后画，保证不被名字盖住。底图可换：高德、百度、OSM 瓦片源三档在设置里各自填 key 就能切，注册表写在 docs/wiki/map-providers.md，不填就还是自绘那一档，算路与画线不经过网络。

过程可见。每次回复下面直接把「它做了什么」摆出来，不藏在折叠里，分三类记录：读了 N 件待办和几节课、模型这一跳的判断、每个工具的名字与参数和结果（失败的置红）。判分里要求的「中间结果可核验」就落在这里，行程卡底部还把排程依据直接写出来：「今天的课：3 节，最晚一节 15:40 下课」「起点用最后一节课的 立德楼，不用先回宿舍」。

三项目计划

3.1 可行性

已经不纸面了。分支上现在是可运行的一套：noticehub/ 93 个 Python 文件、37549 行；tests/ 100 个测试文件、51715 行、2614 条用例；前端 web_static/ 下 11 个手写 js（7851 行）、page.html（476528 字节）、manifest.webmanifest、4 个图标 png 和 icon.svg。数法：git ls-files 取这几个路径下全部 .py，逐文件数物理行（含空行，末行无换行也算一行），前端按目录里实际文件数；代码与用例的机器可核对版本在 docs/contest/facts.json（由 tools/gen_facts.py 生成，tests/test_docs_facts.py 对着它比）。演示版一键启动（demo\启动演示.cmd），跑起来自带 5 件待办、3 节课、1 条常做的事，直接看到两趟行程和地图。

排程是纯函数：同样的输入，两次输出完全一致，有测试盯着。它不依赖网络，也不依赖模型。

云端那组按最常用的五种意图各挑一句：排今天的事 3.2 秒；问取快递顺不顺路 11.9 秒（中间多调了一轮工具）；把还书挪到明天 2.8 秒；在立德楼问附近还有什么没办 2.4 秒；问今天几件、走多少路 2.6 秒。最后一句答的是当时那张行程：2 趟、5 站、1044 米、走路 16 分钟；同一份待办里把还书挪到明天再问一遍，数字跟着变成 4 站、762 米、走路 12 分钟——上一句改的东西这一句回得来，不是每轮从头猜。

异常路径另有专门的用例盯着，不靠手测：同一句里重复调用只执行一次（test_the_same_call_is_not_run_twice_in_one_turn）、模型超时给人话（test_read_timeout_becomes_one_sentence）、未接模型时明说降级（fallback 与断网浮条各一条）、认不出地点仍建单并单列。跑一遍 tests.test_application_agent_chat 是 55 项。

耗时含本机模型自己思考的时间；第一次说话还要等模型装进显存（约一分钟），之后每句如上。这里踩过一个真坑：通用的读超时是 60 秒，第一句话正好卡在装显存那一段（实测 60.6 秒被判超时，失败），现在本机模型一律给足 90 秒；把模型从显存里卸掉再复测，冷启动第一句 59.9 秒成功、返回完整清单。第五句那个「打印店」是故意设计的：校园点位表里没有它，程序不猜。云端那组单次调用给 25 秒上限，超了按降级处理，不会无限等。

已经在用的人。GitHub 仓库 104 star、9 fork；现存 20 个 Release（v1.0.0 到 v1.1.0）附件累计下载 1639 次，拆开是电脑版 zip 1232、手机 APK 407，正式版 492、测试版 1147；单版最高 460 次（beta.2）、454 次（v1.0.0）。近两周仓库浏览 988 次、克隆 1192 次。另有 20 个日期版（v2026.10.8 到 v2026.10.27）当初发过 Release，本地还留着那份发版记录与 16 份发版说明，后来 Release 被删、现在按 tag 查全是 404，那批计数跟着没了——所以 1639 是下限不是上限。抖音两条演示视频 21.9 万播放、收藏 5284（1830 + 3454）。Gitee 镜像同步 17 个版本，接口与页面都不给下载次数，因此只报 GitHub 一个数。取数方式：gh api repos/ExpertKT/notice-hub/releases --paginate 里每个附件的 download_count 逐个相加，流量走 traffic/views 与 traffic/clones（GitHub 只留 14 天），逐条底表随材料一起交。下载不等于在用，也不拿没有埋点的留存率充数。

4.2 数据与隐私

全部数据在本地：SQLite 单文件加几个 JSON，进程退出即停，没有账号体系也没有云端同步。调用云端模型时只发待办的标题与状态，不发群号、昵称和消息原文；钥匙只存在服务端，随请求走请求头，不回传浏览器也不写日志。用本机模型时数据不出机器。

4.3 跑起来的成本

项实际情况
运行环境一台 Windows 电脑（10/11）。演示包自带运行时，双击一个脚本就起；从源码跑要 Python 3.12 以上。都不需要数据库服务、不需要前端构建、不需要装地图 SDK。
模型依赖可选。接云端 OpenAI 兼容接口只要一把钥匙，一句话实测 2.4~3.2 秒；不想联网就本机 Ollama 跑量化模型，零调用成本、数据不出机器；一句输入约 900 字符、输出不到 200 字。
人工干预日常不需要：群消息自动落库、行程自动重排。人手只花在两件事上——补一句「这栋楼在哪」、改课表。

换一所学校要改什么。只改数据，不改代码：campus_poi.json 里换成自己学校的楼（名称、别名、相对坐标、营业时间），课表贴一段文字或者选一张截图导一份。campus_poi.json 与课表都在数据目录里，覆盖内置值就生效。排程、校验、地图渲染都不绑定具体校区。

往下还能做。把行程分享成一张图发到群里、群通知自动抽出地点而不只是标题、多学期课表并存。这三件事都有明确落点，不需要改架构。

4.4 怎么跑起来

  1. 解压后双击 启动演示.cmd（Windows 10/11，不用装 Python，也不用装任何运行库）。
  2. 脚本自动写好演示数据并打开浏览器：http://127.0.0.1:8899/?token=demo&demo=1&nowiz=1，关闭命令行窗口即停止。演示包里不带钥匙：自己把一行 key 写进包根目录的 llm.key 才有真对话，启动窗口会打印「模型：云端接口」，输入框里说话就是真模型在决定调哪个工具，一句两三秒；没放就退成固定说法并在页面上说明，行程和地图不受影响。
  3. 顶部是今天几趟：右栏上面是校园地图，下面两趟行程，每站有到达时间与理由；窗口拉窄就并成一栏。
  4. 点底部输入条跟它说话：「武进楼还有个物理报告周四要交，回宿舍前帮我把生活用品取了」。回复下面就是「它做了什么」，不用再点：读了哪几件、调了哪个工具、参数是什么、成没成。
  5. 手机：同一局域网内用手机打开地址，浏览器菜单里「添加到主屏幕」，之后从桌面图标进，全屏无地址栏。
