# 群务台 · 作品说明

> 一句话：群消息里的通知变成待办，待办再排成今天几趟路。

关键词：通知聚合 · 智能体调度 · 路径安排规划 · 便携式。

参赛赛道：二（工具调度与自主任务智能体）。同目录另有《群务台项目计划书.pdf》《操作说明.md》《演示脚本.md》。

## 一、解决谁的问题

常州大学西太湖校区，班群、助教群、社团群一天几十条消息。实验报告周五 23:59 截止，这句话埋在某条四百字通知中间；交班会材料要送到立行楼 302；还书得跑图书馆；生活用品在学生公寓 A。这些事分散在教学楼、图书馆、食堂和宿舍之间，单程都在十分钟上下，而一个下午只剩课与课之间那一百来分钟。

现有工具各管一段：群消息靠人往上翻，待办清单只回答「有什么」，地图只认地名、不认「这件事在哪办、几点关」。学生自己心里的算法是：拿最后一节课下课的楼当起点，把顺路的几件串成一趟。群务台把这套算法写成了程序。

## 二、它是什么

三条数据流，各自独立：

1. **收**。NapCat 把 QQ 群消息 POST 到 8765，receiver 落库、按白名单过滤，service 攒批交给 summarizer，产出标题、截止时间、置信度，拿不准的进「候选」等用户确认。推送走 QQ 机器人、WxPusher、Server 酱、PushPlus 或 Webhook。
2. **看**。待办台按今天 / 本周 / 以后 / 已完成分组，可导出 .ics 给系统日历，数据落在安装目录的 SQLite 里。
3. **排**。这一版新加的一层：`/api/agent/plan` 把课表、待办、常做的事、校区地点合成「今天几趟」。

排程坏了不影响收消息，模型连不上不影响排程。这条边界是刻意划的。

## 三、智能体的决策链

用户说一句「周四下午交实验报告、还书，顺路吃饭」，后端会走完一条完整的链（`noticehub/application/agent_chat.py` 的 `chat_turn()`）。

**读**。先把上下文摆到模型面前，同时落一条 trace：「读了 5 件待办、今天还有 3 节课（最后一节 15:40 下课），和刚才 0 轮对话」；课上完了就换成「读了 5 件待办、今天的课都上完了」。课表读不到就少这一句，不拖垮对话。

**想**。模型只被允许回一个 JSON：`{"say": "...", "calls": [...]}`，系统提示里写明工具名只能取 `act / create / rename / pin / urgent / reschedule / clear_finished` 七个之一。模型要说的话写进 say，这条进 trace 的「想」。

**调**。每轮最多取 3 个调用，同一个调用键去重，总共两轮。每个调用执行完记一条 `{"kind": "call", "tool", "args", "ok", "detail"}`，页面上渲染成「改期（第几件 2，截止 11 月 19 日 15:00）：」后面接工具返回的那句话。参数也翻成中文，不会把 `2026-11-19T15:00` 的原文甩在屏幕上。

**回流**。执行结果拼回下一轮对话，模型据此决定还要不要动手。两轮用完就收，不无限循环。

页面上这块叫「它做了什么」，默认摊开。原因写在代码注释里：折叠起来只剩一行标题，等于把过程藏了。

### 失败与越界怎么处理

护栏写在代码里，不靠提示词祈祷：

- 白名单之外的工具名，执行不了。
- 删除和清空要二次确认：第一次只记 pending，用户回「确认」才真动手。
- 还在进行、又不是手动建的任务，只许「忽略」，不许删。
- 说「第 3 件」但对应不上，或者标题对上好几件，就把候选列出来让用户说全，不猜。
- 模型没产生任何动作、而用户话里带动作词（「删掉」「改到」），补一轮重试。
- 模型超时按人话报：「模型太慢，这一轮没等到回应」。云端单次调用 25 秒上限，本机模型 90 秒硬顶。
- 会话存在进程内存里，重启就丢。这是限制，写在第八节。

## 四、排程：这一层刻意不碰模型

`noticehub/application/trips.py` 开头写着：地点识别有规则兜底，聚类、排序、步行时间、截止校验全是本地计算，所以模型连不上时行程依旧排得出来。

输入是今天的课表、带地点和截止的待办、常做的事（比如「第一餐厅 吃饭 30 分钟」）。算法：

- 用课表挖空档，短于 25 分钟不算一趟；
- 起点取今天最后一节课所在的楼，不用先回宿舍；
- 同一片区的点先聚，区内按最近邻排；
- 步行按 70 米/分钟折算，含进楼、找教室、等电梯，每站留 10 分钟办事；
- 塞不下或会错过截止的进 overflow，写「这一趟塞不下，建议明天上午或提前出发」；
- 办事窗口会关的，给一句「XX 的办事窗口到 17:30 就关，这趟可能会白跑」。

每一站都带一句「为什么是这个顺序」，只写算出来的事实：「就在下课的这栋楼里，顺路先办」「接着走 283 米，比再跑一趟省一次往返」。页面另给一段核对句：「起点用最后一节课的立德楼，不用先回宿舍」「这一趟 4 件、走路 10 分钟，15:40 出发」。用户不必信，自己核。

算出来的顺序不是终稿。用户可以把「常做的事」直接拖进行程里、也可以拖着某一站换位置；松手后这份站序会发给服务端存下来（`action=order`，落数据目录的 `campus_plan_order.json`，留最近 14 天），刷新、第二天再来都还在。存不上时不回滚页面上的顺序——用户刚摆好，回滚等于「什么都没发生」——改成明说「顺序没存上，刷新会回到按远近排的走法」。小组内手排优先于最近邻，跨区仍然按片区成趟，不会为了顺序把行程拆散。

拿演示数据算（`demo/seed.py` 的 seed，按平面图上的 27 处地点重算）：6 件、2 趟、走路 16 分钟、997 米。第 1 趟教学区 15:40–16:30，4 件、571 米、走路 9 分钟：15:40 立德楼 512 找同学拿材料，15:53 立行楼 302 交班会材料，16:09 武进楼 B203 交大学物理实验报告，16:20 图书馆还书；第 2 趟生活区 16:39–17:22，2 件、426 米、走路 7 分钟：16:39 第一餐厅吃饭，17:12 1 号楼取生活用品。27 处地点全部认出，0 件排不进去。这份数据可复现，`demo/启动演示.cmd` 的 seed 就是它，`tests/test_application_trips.py` 锁着「2 趟、6 站、997 米」。

## 五、地图

校区画在米制平面上：西南角为原点，x 向东、y 向南。不用经纬度，因为这套计算只关心相对距离。地点存在数据目录的 `campus_poi.json` 里，每条带别名、片区、坐标、类型和营业窗口。加载时先铺一份内置的，再用文件里的同 id 条目盖上去；写一个新的 id 就多一个地点，不用改程序。文件写坏或某条缺坐标，那条当不存在，照旧用内置的——排程不该因为一份 JSON 写错就崩。换学校，换的也是这份文件。

页面上是真 3D：每栋楼按轮廓挤成体块，打一盏光、落下影子，能拖着转视角；没有 WebGL 时退回 SVG 平面图。两种画法共用一份数据，坐标来自 `/api/agent/plan`，页面不自己编数字。

## 六、手机端

手机是第一现场，所以三件事都做了。

**手机模式**。网页在窄屏上不是把桌面版缩小：概览压成一句话「今天 2 趟 · 最近 20:00 · 完成 0/12」，右边一个「展开」；待办卡片整块跟在下面，地图拿到剩余高度；底栏四个常去的地方（待办 / 详情 / 最近推送 / 收件箱），顶栏一键切回桌面版。`?phone=1` 可以直进手机模式，退出时地址栏参数会自己清掉。

**可安装**。`manifest.webmanifest` 里 display 是 standalone，图标有 192、512 和 maskable 版本，iPhone 加到主屏幕后没有地址栏。service worker 只缓存外壳（manifest、图标、首页）、`/api/` 一律不缓存，但它只在本机 `127.0.0.1` 或 https 下才会注册——手机用 `http://电脑IP:端口` 打开时浏览器不给 service worker（实测 `isSecureContext: false`），所以手机上没有离线外壳，这跟「数据在电脑上」是一回事。安卓另有 APK，扫码配对，6 位数字码兜底，它是电脑服务的外壳。

**微信小程序**。`miniprogram/` 是同一条数据流的第二个入口：待办、对话、地图、设置四页，tabBar 三个 tab，深色主题跟着系统的 `darkmode` 走（`theme.json` 一套变量），触控尺寸 88rpx，空态、骨架屏、长文本截断都做了；地图用的是和网页同一份 27 处校区地点（`assets/campus.js` 由 `DEFAULT_POIS` 生成，名字与别名按长度倒序匹配，「11 号楼」不会抢走「1 号楼」）。静态检查 `checks/check.cjs` 跑 `node` 一把过（页面与配置、HTTP 失败分类、对话成功/降级/取消、看板解析、地点别名优先级、地图选中与标签抽稀、深色逐页）。它连的是本机服务，所以在开发者工具里演示；真机要服务所在电脑在同一个局域网。

## 七、装起来试

Windows 10/11 加 Python 3.12 以上，双击 `demo/启动演示.cmd`。它在 8899 端口起一份独立实例，数据在 `demo/data`，不碰装在 8766 的那份。脚本先写 5 件待办、3 节课、1 条常做的事，再打开 `http://127.0.0.1:8899/?token=demo&demo=1&nowiz=1`。模型按启动器同目录的 `llm.key` 选：源码版放在 `demo\llm.key`，安装版放在包根目录。写了钥匙就走云端 OpenAI 兼容接口，没写时后端设为 `auto`，对话用固定说法并当场说明，排程照常。

## 八、已知限制

1. 地点坐标是按校园示意估的，不是测绘数据。步行按 70 米/分钟折算，跟真实走法有出入。
2. 区内排序用最近邻，不是最优解，点多时会明显绕。
3. 课表截图识别后先给草稿，要人核对再存，不直接落库。
4. 会话在进程内存里，重启服务，对话就断。
5. 单人单机：没做多用户、权限和云同步。
6. 断网时只能打开外壳，数据请求会失败。`/api/` 不缓存是故意的。
7. 小程序要连本机服务，只在开发者工具里验过；真机演示得让服务所在电脑和手机在同一局域网，深色主题也没在真机上逐页核过。

- **模型**：云端 `deepseek-flash`（实现测一句 2.4~3.2 秒）；端点可换成任意 OpenAI 兼容服务。本机 Ollama 的 `qwen3.6:35b-a3b-q4_k_m-gpu20` 只在手动把 `NOTICEHUB_LLM_BACKEND` 设成 `ollama` 时用。模型只负责把话说成 JSON、挑出通知，排序与校验不走模型。
- 其余为 Python 标准库与仓库自身代码，数据落本地 SQLite。
