## 和字面契约不同、但按现有测试留下的

1. 任务不存在时，`set_task_urgent` / `set_task_pinned` 的用例返回 `{"ok": false, "error": "任务不存在"}`。HTTP 仍是 404。`tests/test_webapp.py` 锁的是 404。已完成任务不能置顶的文案没改。
2. 收件箱分类的 `limit` 超出 1–20000 仍回 400「提取条数必须在 1 到 20000 之间」，没有改成钳制。
3. `POST /api/inbox/classify/cancel` 仍留在网页里。没有任务在跑时它回 200。历史取消才是 `cancel_job`，没有在跑时回 409「当前没有正在运行的回溯任务」。
4. 日历正文仍由 `qq_live_digest.ics.render_calendar` 生成。鉴权留在网页。`/api/sync/info` 的事件条数数的是同一份正文。
5. 历史和分类的任务槽仍是网页进程里的 `_JOB_STATE`。用例接收已经探测好的地址、快照函数和 `catchup` / `inbox`，不在用例里读环境。
