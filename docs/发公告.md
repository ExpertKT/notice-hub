# 发公告流程与工具

## 快速开始

### 1. 添加公告

```bash
python tools/announce.py add --title "学习通 Cookie 到期提示" --body "在设置页点「一键获取 Cookie」重新授权。"
```

自动生成 ID（日期 + 标题 slug），打印新增公告的完整 JSON。

### 2. 验证格式

```bash
python tools/announce.py validate
```

检查 `announcements.json` 的结构、字段类型、日期格式、ID 唯一性。失败时打印错误行。

### 3. 发布到仓库

```bash
git add announcements.json
git commit -m "添加公告：学习通 Cookie 到期提示"
git -c "http.https://github.com.proxy=" push
```

**重要**：本仓 push 必须用 `git -c "http.https://github.com.proxy=" push`，否则被本地代理配置挡住。

### 4. 客户端何时看到

- **GitHub raw CDN 缓存**：一般 5-15 分钟
- **客户端本地缓存**：6 小时
- **最坏延迟**：raw URL CDN 过期 + 用户手动重启 = **~15 分钟 + 最后一次启动时间**
- **急事解决方案**：让用户点「设置 → 重新检测」或重启应用（客户端 `active()` 会忽略本地缓存）

## 详细用法

### `list` —— 列出所有公告

```bash
python tools/announce.py list
```

输出：日期、ID、标题。

### `add` —— 添加新公告

```bash
python tools/announce.py add \
  --title "某来源暂时不可用" \
  --body "由于网络问题，今天早上 07:00-09:00 无法同步。请稍候。" \
  --level warn \
  --min-version "1.0.0" \
  --max-version "1.1.0" \
  --channel beta \
  --sticky
```

参数说明：

| 参数 | 必须 | 说明 |
|------|------|------|
| `--title` | ✓ | 公告标题 |
| `--body` | ✓ | 公告内容，支持 `\n` 换行与 `- ` 列表 |
| `--level` | 否 | `info`（默认）/ `warn` / `critical`；决定弹窗配色与必读标记 |
| `--url` | 否 | 可选链接（如 release notes、讨论帖） |
| `--min-version` | 否 | 最低版本，空 = 无限制（例 `1.1.0-beta.1`） |
| `--max-version` | 否 | 最高版本，空 = 无限制 |
| `--channel` | 否 | `stable` / `beta`，空 = 所有通道 |
| `--sticky` | 否 | 每次启动都弹（默认只弹一次） |
| `--id` | 否 | 自定义 ID；留空则自动生成 `<日期>-<slug>[-N]` |
| `--date` | 否 | 日期（`YYYY-MM-DD`），留空用今天 |

### `remove` —— 删除公告

```bash
python tools/announce.py remove --id "2026-10-11-cookie-renew"
```

按 ID 删除。

### `validate` —— 检查格式

```bash
python tools/announce.py validate
```

检查项目：

- 根是 dict，含 `version` 和 `items`
- `items` 是 list
- 每条必须有 `id` 和 `title`（非空）
- 无重复 ID
- `level` 只能是 `info` / `warn` / `critical`
- `date` 格式 `YYYY-MM-DD`
- `sticky` 是 bool

失败时打印错误行；成功打印 `OK`。

## 现成例子

### 例子 1：学习通 Cookie 到期提示

```bash
python tools/announce.py add \
  --title "学习通 Cookie 已过期，需要重新授权" \
  --body "请在设置页点「一键获取 Cookie」重新授权。\n\n如果你的 Cookie 曾在多台电脑上登录过同一个学习通账号，需要逐台更新。" \
  --level info \
  --url "https://github.com/ExpertKT/notice-hub/issues/42" \
  --channel beta
```

用户场景：单独通知某类用户（beta 测试者），不是强制。

### 例子 2：某来源临时不可用

```bash
python tools/announce.py add \
  --title "钉钉接入服务维护" \
  --body "由于基础设施升级，今天 14:00-15:30 钉钉来源可能无法同步。其他消息源正常。" \
  --level warn \
  --sticky
```

用户场景：突发故障通知所有用户，每次启动都弹（`--sticky`）直到用户手动关闭。

## 技术细节

### 版本号比较（`min_version` / `max_version`）

- 格式：`1.0.0`（发布版）或 `1.0.0-beta.1`（预发布）
- 比较规则：`1.0.0-beta < 1.0.0-rc.1 < 1.0.0 < 1.0.1`
- 空值 = 无限制
- 客户端代码实现见 `qq_live_digest/announce.py:_ver_tuple()`

### JSON 结构

```json
{
  "version": 1,
  "items": [
    {
      "id": "2026-10-11-cookie-renew",
      "date": "2026-10-11",
      "level": "info",
      "title": "学习通 Cookie 到期了怎么办",
      "body": "在设置页点「一键获取 Cookie」…",
      "url": "https://github.com/ExpertKT/notice-hub/releases/tag/v1.1.0",
      "min_version": "1.1.0-beta.1",
      "max_version": "",
      "channel": "beta",
      "sticky": false
    }
  ]
}
```

字段语义：

| 字段 | 类型 | 必须 | 说明 |
|------|------|------|------|
| `id` | str | ✓ | 全局唯一，客户端靠它记「已读」 |
| `date` | str | ✓ | 发布日期（`YYYY-MM-DD`） |
| `level` | str | ✓ | `info` / `warn` / `critical`；`critical` 需要用户点掉 |
| `title` | str | ✓ | 标题 |
| `body` | str | ✓ | 内容（支持 `\n` 换行与 `- ` 列表） |
| `url` | str | 否 | 可选链接 |
| `min_version` | str | 否 | 最低版本（空 = 无限制） |
| `max_version` | str | 否 | 最高版本（空 = 无限制） |
| `channel` | str | 否 | 通道过滤（空 = 所有） |
| `sticky` | bool | ✓ | 每次启动都弹 |

### 后端代码

- `qq_live_digest/announce.py` — `fetch()` / `parse()` / `active()` 三个函数
  - 不联网：`fetch()` 从 GitHub raw URL 拉取，失败读本地缓存，永不抛异常
  - 过滤：按版本区间、通道、黏性标记
  - 排序：按日期倒序（最新优先）
- `tools/announce.py` — CLI 工具，只改仓库根 `announcements.json`，不联网、不 commit、不 push
