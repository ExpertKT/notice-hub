# 群通知待办台 UI Taste 规范

面向 `qq_live_digest/webapp.py` 的单页本地界面：QQ 群通知转待办与日历。目标是让用户快速判断下一步并确认操作结果。允许有克制的 3D 景深和镜头感；不允许为了展示动效而牺牲可读性、速度或状态真实性。

## 约束与来源

页面是内联 HTML/CSS/JS，离线、零依赖、无构建步骤、无 CDN。只使用浏览器原生 CSS、JavaScript、DOM 和必要的内联 SVG。禁止 npm、框架、外链脚本/样式/字体、远端图片、WebGL 库、Lottie runtime。系统字体栈优先；图标用文字、CSS 或内联 SVG。采用的来源及比较见 `.reports/task-taste.md`。本规范的尺寸、时间、角度和评分阈值是针对本产品的可测设计决策，不冒充来源仓库原文。

## 1. 信息层级与布局

1. 页面首屏先显示当前待处理数量或状态、主要待办和明确的主操作；装饰 3D 场景不得占据比待办内容更大的视觉面积。
2. 全页只用 4 个文字层级：页面标题 24–28px/1.25，区块标题 18–20px/1.35，正文 15–16px/1.5，辅助信息 12–13px/1.45。手机正文不得小于 14px。
3. 间距采用 4px 基准、8px 主步进：4/8/12/16/24/32/40px；布局间距仅从此表取值，例外需有控件尺寸理由。
4. 页面左右内边距窄屏 16px、宽屏 24px；内容容器最大宽度 960px，并水平居中。
5. 同组内部间距 8 或 12px；不同区块间距至少 24px；主标题到首个内容区间距 24–32px。
6. 交互控件点击目标至少 44×44px；相邻可点击目标间至少 8px。禁止靠微小图标作为唯一操作入口。
7. 每条待办的标题、截止时间、来源/群组和完成状态必须可扫读；状态不可只靠颜色表达。
8. 页面在 320px 宽视口不得横向溢出；长标题允许换行，不得压缩操作目标或遮盖时间信息。

## 2. 色彩与可读性

9. 建立不超过 6 个语义色角色：背景、表面、主文字、次文字、强调/行动、成功/警告/错误状态；避免任意逐组件造色。
10. 正文与背景对比度至少 4.5:1；大字（至少 24px 常规或 18.66px 粗体）及必要图形/控件边界至少 3:1。按 WCAG 2.2 AA 对比度算法核验。
11. 次要信息仍需达到 4.5:1；不得用降低透明度的方式让可读文字低于目标。
12. 成功、失败、逾期等状态同时用文字/图标/形态提示，不得仅用红绿区分；焦点环对相邻颜色至少 3:1。
13. 页面保持一个主强调色；成功/警告/错误色仅用于真实状态，不作常驻装饰。

## 3. 3D 与景深

14. 3D 只用于局部任务面板、分层背景或聚焦提示；待办文本平面保持正视、无透视变形。
15. `perspective` 使用 800–1400px；面板 `rotateX`/`rotateY` 常态不超过 2deg，指针跟随最大 4deg，触屏设备不做指针追踪。
16. `translateZ` 分层控制在 0–24px；最多 3 个深度层，层级差至少 6px，避免大幅浮起产生游戏化错觉。
17. 景深优先由 2–3 档柔和阴影及低强度背景遮罩构成；阴影模糊半径 8–24px、透明度 0.08–0.22，不以大范围模糊遮挡信息。
18. 使用 `transform: perspective(...) translateZ(...) rotateX(...)` 等原生 CSS；3D 必须有明确聚焦或层次作用，不得整页持续旋转。
19. `will-change` 仅在开始过渡前临时添加，结束后移除；不得给全页或所有列表项常驻 `will-change`。
20. 无法稳定合成或文字变糊时，删除 Z 轴变换，改用层级阴影、边框和明暗差；减少运动模式下取消倾斜与深度位移。

## 4. 运镜与动效

21. 只为有因果关系的状态变化动画：页面/区块进入、视图切换、操作聚焦、待办完成反馈。无状态变化不得播放“庆祝”动画。
22. 页面初次进入只做一次轻微镜头推进：缩放 0.985→1、Y 位移 8–12px，时长 220–320ms；不做全屏飞入或持续漂浮。
23. 局部视图切换以同一锚点位移 8–20px、缩放 0.98→1，时长 180–260ms；相邻元素错峰不超过 40ms。
24. 聚焦待办可将目标放大至 1.01–1.025，并使非目标仅降低表面强调（不可降低文字对比度），时长 160–220ms；退出时回到原位。
25. 按压反馈 80–140ms，使用 scale(0.97–0.99)；回弹不超过 180ms，不得影响按钮布局尺寸。
26. 进入使用 `cubic-bezier(0.2, 0.8, 0.2, 1)`；退出使用 `cubic-bezier(0.4, 0, 1, 1)`；禁止弹簧过冲、无限循环和超过 500ms 的常规 UI 过渡。
27. 动画只改变 `transform`、`opacity`；不得逐帧动画 `top/left/width/height/margin`、阴影模糊或大面积滤镜。静态阴影可切换但不连续插值。
28. 禁止滚动视差、鼠标驱动的全局摄像机、自动播放背景动画、无意义粒子、长时间 skeleton 闪烁；以静态层级或一次性小幅过渡替代。

## 5. 操作确认与真实状态

29. 按下：在 100ms 内出现压低/缩小反馈；按钮仍保持可见焦点和可读标签。
30. 进行中：真实请求发出后禁用重复提交，在 100ms 内显示明确进行中文案或原生进度状态；不得提前显示成功。
31. 成功：仅在服务端成功响应且本地状态同步后，显示“已完成”等文字/状态标记，并执行 140–220ms 的轻量淡出/归位；保留撤销或恢复路径若原有业务支持。
32. 失败：恢复可操作状态，保留原待办数据，在 100ms 内显示可理解的错误说明和重试入口；不播放成功动效，不静默吞错。
33. 任何请求超时/失败不得乐观移除待办；若已有乐观更新，失败时必须恢复原状态并告知用户。
34. 日历切月后标题与日期格必须来自同一实际月份状态；仅在渲染完成后执行方向一致的 8–16px 过渡，不做假镜头切换。
35. 键盘操作与指针操作产生相同业务状态；焦点可见，动画不作为唯一状态反馈，状态提示可被辅助技术读取。

## 6. 性能、适配与降级

36. `prefers-reduced-motion: reduce` 时，禁用非必要空间位移、缩放、倾斜和错峰；状态仍通过文字、图标、边框/背景即时变化表达。过渡时长降至 0–100ms。
37. 任何持续动画必须有暂停/停止途径；本规范不允许无业务必要的持续动画，因此默认不得有常驻动画。
38. 不在滚动/鼠标事件中反复读取布局后写样式；用 CSS hover/focus/active 与事件委托，必要 JS 更新在单次事件中集中写入。
39. 首屏不请求外网、不加载字体/脚本/图片；断网时主要待办和日历操作仍可用（数据能力以既有本地服务为准）。
40. 低性能设备或 3D 不受支持时，页面必须完整退化为平面布局；装饰层隐藏不影响操作与信息。

## 7. 自检评分表

实现者在交接报告逐项填 0 或 1；只有通过右侧可判定项才计 1。至少 18/20 且无安全、真实状态、对比度、Reduced Motion 项失败，才可交付；任一红线失败即不通过。

## 8. 反例清单

- 整页做成倾斜的透视舞台，文字也跟着旋转。
- 点击完成先把任务飞走，再发请求；失败时任务消失或状态对不上。
- 所有卡片悬浮、呼吸、泛光，用户无法判断哪个状态重要。
- 用 1 秒以上的长转场、夸张弹跳或连续自动运镜包装普通切换。
- 用灰化透明文字制造“景深”，导致对比度不足。
- 对整页常驻 `will-change: transform`，或对每个列表项创建合成层。
- 为了 3D 引入 Three.js、GSAP、Lottie、React、npm/CDN/远端字体。该项目无法保证安装/构建/离线访问；替代是原生 CSS transform、短 JS 状态类切换、系统字体和内联 SVG。
- 用仅颜色、仅动效或仅声音表达成功/失败。
- `prefers-reduced-motion` 下仍保留视差、缩放和错峰。
- 把原生滚动条/键盘焦点移除，或把小于 44px 的图标当作唯一触控入口。
