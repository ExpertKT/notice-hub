# 桌面浮球阶段 1：接口与字段清单

关联页面：`qq_live_digest/floatball_page.py`（`render() -> str`）。页面同源运行，只使用浏览器原生 `fetch`，不调用 setup/其他页面 API。

## 调用接口

| 接口 | 用途 | 页面处理 |
|---|---|---|
| `GET /api/tasks` | 获取任务分组和置顶项 | 首次加载、点击刷新、页面回到前台及每 60 秒更新；以 `today + week + later + candidates + pinned` 合并并按 `id` 去重；忽略已完成/已忽略/已过期项。 |
| `GET /api/inbox?limit=100` | 关联原文、群名和发送人 | 独立加载，失败时任务照常显示；只使用这次最多 100 条返回结果，未匹配时不显示发送人。 |
| `POST /api/tasks/{id}` | 完成、稍后、忽略、候选确认 | body 分别为 `{"action":"done"}`、`{"action":"snooze"}`、`{"action":"dismiss"}`、`{"action":"confirm"}`。收到成功响应后刷新任务列表；候选显示「确认待办」。 |
| `POST /api/tasks/pin` | 置顶/取消置顶 | body 为 `{"task_id":"<id>","pinned":true|false}`；成功后刷新列表。 |

所有请求从 `location.search` 读取 `token`，只通过 `X-Token` 请求头传递，不写入 `localStorage`、不放进 API URL。HTTP 非成功或 JSON `ok:false` 均按失败处理；服务端 `error`/`reason` 有值时显示原因为页面状态，操作失败不乐观移除任务。

## 字段与缺省显示

### `/api/tasks`

- `today`、`week`、`later`、`candidates`、`pinned`：缺失或非数组按空数组；用于浮球列表。`done`、`stats` 不用于阶段 1 浮球展示。
- `id`：动作请求必需的正整数 ID；缺失/非数字时跳过该任务（防止对错误 URL 发 POST）。
- `task_key`：可选，用于与 `inbox.msg_id` 关联；缺失时仍尝试用 `id` 与 `inbox.task_id` 匹配。
- `summary`：缺失或空时显示「未命名事项」。
- `effective_urgent`：只按服务端布尔值决定紧急优先/「紧急」标记；缺失按非紧急处理，不从 `importance` 或 `urgent_override` 自行推导。
- `deadline`：用于排序；空值或不可解析时排在有有效截止时间的任务之后。
- `deadline_text`：详情/摘要行显示；空时不显示截止时间。
- `groups`：数组，合并显示；空时尝试用已匹配 inbox 的 `group_name`，仍为空则不显示群组行。
- `source_text`：详情显示原文；空时不显示该项。
- `details`：补充详情，兼容数组或标量；空时不显示。
- `pinned`：空/缺失视为未置顶；置顶按钮以服务器返回状态为准。
- `status`、`done`：用于识别候选与排除已完成/已关闭记录；候选用 `confirm`，普通待办用 `done`。
- `created_at`：仅用于「新」标记；缺失或无效时不标新。

### `/api/inbox`

- 响应 `items`：缺失或非数组按空数组；`/api/inbox?limit=100` 只查一页，不递归翻页。
- `task_id`：优先和任务 `id` 字符串比较。
- `msg_id`：若未通过 `task_id` 命中，再与任务 `task_key` 比较。
- 只有关联成功后才展示 `group_name`、`sender_name`、`content`；各字段为空则单独省略。不能关联时只显示任务自身的 `groups` / `source_text`，绝不从正文猜发送人。
- `received_at`：当任务 `created_at` 不可用时，作为「新」标记时间；无效则不标新。
- `source`、`event`、`group_id`、`verdict`、`reason`、`method`：阶段 1 不展示。

## 角标与「新」的定义

- 角标 = `/api/tasks` 返回的 `candidates.length + today.length + week.length`；不把 `pinned` 重复计数，也不把 `later` 计入。超过 99 显示 `99+`。
- 无服务端未读游标；每次打开列表前读取 `localStorage['nh_floatball_last_open']` 作为上次打开时间，再写入当前 ISO 时间。`created_at`（无效时回退到匹配项 `received_at`）晚于上次时间才标「新」；没有历史打开时间时不把旧任务全部标新。储存失败时列表仍可用，仅关闭新标记。

## 限制与失败显示

- task API 失败：保留已加载数据（若有）、显示接口错误，并提供重试；首次失败时展示重试按钮，不渲染空白假列表。
- inbox API 失败或匹配不到：任务仍显示；发送人/消息原文扩展信息不显示，并在面板状态区说明收件箱详情不可用。
- 动作失败：不做乐观状态更新，恢复按钮并显示服务端/网络错误；成功后才执行完成淡出与列表刷新。
- 阶段 1 不实现首次提醒设置、系统气泡、提示音、全屏隐藏或位置持久化；这些留待阶段 2。
