## 1. 全量测试

- **命令**：`.\.venv\Scripts\python.exe -m unittest discover -s tests -t .`
- **记录**：`Ran N tests`、`OK`（或 `FAILED`）、耗时（正常约 63 秒）。
- **怎么验**：连跑两遍，把两遍输出原文贴进第 7 节记录表。两遍的 `Ran N tests` 数字一致、且都是 `OK` 才算过。只写「通过」不算。
- **谁验**：验收人本人在自己机器上跑。

## 2. 包内容

- **产物**：`packaging/build.ps1` 产出 `packaging/QQ-Notice-Hub.zip`。
- **记录**：zip 字节数、sha256（`Get-FileHash -Algorithm SHA256`）、条目数。
- **包内必须有** `_internal/qq_live_digest/web_static/page.html`。
- **包内版本号**必须等于 `qq_live_digest/version.py` 里的 `APP_VERSION`。
- **通过标准**：条目数不为 0，四项（字节数、sha256、page.html、版本号）都登记在记录表里。

## 3. 升级链路（上一版 → 本次）

照 `notice-hub-cold-install-verify` 的做法，在临时目录 + 随机端口跑，**不碰用户的正式实例**。

1. 冷装上一版，启动，确认页面版本是上一版。
2. 带 `?check=1` 打开页面（强制检查更新，`qq_live_digest/webapp.py:2650`），能看到新版。
3. 下载，本地复算 sha256，与 Release 上登记的 sha256 一致。
4. apply，重启后版本号与页面 badge 都变成新版。

**通过标准**：四步都拿到预期值。sha256 对不上立刻停，不许继续。

## 4. 界面截图（必须真的看图）

- 两种宽度各一遍：1280、390；暗色、亮色各一遍。
- 每个要验的元素：先 `element.scrollIntoView()`，再取 `getBoundingClientRect()`，把 rect 和当时视口宽高一起记下来，确认元素完整落在视口内。
- 截图文件名写进记录表。截图人必须打开图看：图里目标元素不可见、被遮挡、被截断，就不算过。

## 5. 写接口护栏

- 不带 confirm 调用 `/api/tunnel/start`：必须返回 400 + `needs_confirm: true`（`qq_live_digest/webapp.py:3331`）。
- 测试/只读模式下改本机网络设置的接口：必须 403（`qq_live_digest/webapp.py:3327`）。
- 每次提权动作在日志目录的 `host-actions.log` 里有记录（`qq_live_digest/host_actions.py:28`）。

**禁止在真机上点写接口**，只在这三处验证。
