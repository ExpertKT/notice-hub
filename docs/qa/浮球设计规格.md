# 桌面浮窗设计规格（第一批）

状态：视觉/交互规格；不是接口合同，也不是生产实现。原型数据为静态假数据。技术前提：Edge 应用窗口 + Win32 去边框。窗口不透明，但支持置顶、窗口级拖动和尺寸变化；设计不限定必须是球形悬浮窗。

## 设计目标

让用户不切到群务台也能知道「有几条需要看」，并快速处理一条；收起态安静、紧凑，展开态是同一个窗口里的清晰卡片内容。视觉延续仓库既有群务台的青绿强调色和清晰卡片，不另起视觉体系。浮窗不承担托盘职责，也不展示超出已有任务/通知数据的推断。

## 宿主尺寸通知约定

页面在状态值变化时更新 `document.title`，宿主轮询标题并调整同一个窗口：收起态为 `nh-floatball:closed`（72×72px），展开态为 `nh-floatball:open`（380×600px）。页面不得在每次渲染时重复写标题。

## 两种外观方案（同一窗口）

两种方案共用展开态信息层级、配色 token、任务排序、交互和动效；差异只在收起态轮廓、占屏面积与品牌识别。两者均是不透明窗口，不模拟透明球体。

### 方案 A：贴边竖胶囊（推荐）

- **收起态：宿主窗口固定为 72×72px**；视觉上沿用右下角不透明浮球入口。圆角 24px，底色 `--paper`、1px `--line` 描边。上方保留 10px 拖动纹，中央使用 34px 青绿消息图标，下方清晰显示未读数；最近一条 `summary` 以两行截断显示。用户一眼记住「屏幕边上的青绿通知胶囊」，长轴方向也提示它可展开。
- **展开态：同一宿主窗口固定为 380×600px**；页面内容宽度 380px，高度超出时在窗口内滚动。靠右停靠时向左展开。窄屏宽度限于可用视口减 24px。角标/未读数沿用 20px 最小直径、12px/16px/700 字号；数字超过 99 显示 `99+`。
- **拖动：**胶囊顶端固定 10px 横纹拖动区；整块窗口可通过宿主窗口级拖动。释放后吸附最近屏幕侧边，纵向限制在可用工作区内。
- **窗口尺寸变化：**打开/收起由宿主调整同一个 Edge 窗口，不另建 overlay；固定右边缘锚点，收起窗口 72×72px，展开窗口 380×600px。10px 拖动区位置不变；内容节点保留，先稳定调整窗口边界，再对内容作 200ms 淡入/6px 位移，避免列表重建、滚动位置归零和文字横向跳动。
- **明暗：**浅色时 `--paper` 卡片、`--line` 轮廓、`--teal` 图标、`--red` 数字徽标；暗色时继承同名 dark token，边界用 `--line` 保持可辨，阴影不透明度约 .35。紧急状态仍有文字标签，不仅靠颜色。

### 方案 B：圆角品牌贴纸卡

- **收起态：72×72px** 方形圆角贴纸，圆角 18px；`--paper` 底色、1px `--line` 描边、阴影 `0 4px 12px rgba(0,0,0,.18)`。中心放 40px 的 `--teal` 消息图形，右上角叠加未读徽标；整体像一枚固定在桌面的群务台标记，图形+数字组合具有品牌记忆点，且比胶囊更像独立小工具。
- **展开态：**同一窗口固定为 380×600px，内容超出时在窗口内滚动；靠右时向左展开。用同一固定顶部拖动纹与 10px 手柄；其余行、详情、按钮完全共用，不另造交互。
- **拖动：**顶部固定 10px 拖动条为主要入口，也允许宿主将收起态卡片窗口整体设为可拖动区域；点击图标/数字展开，拖动条负责拖动，减少误开。
- **窗口尺寸变化：**固定右下角锚点，同一个窗口在 72×72px 与 380×600px 之间切换；先由宿主改窗口边界，再淡入内容，保留 DOM、焦点和滚动位置，避免内容跳动。
- **明暗：**与 A 相同，外壳用 `--paper`/`--line`，图标使用 `--teal`，徽标使用 `--red`；暗色由既有变量覆盖，不硬编码另套品牌色。

### 推荐

推荐 **方案 A 贴边竖胶囊**：最近摘要可以在未展开时直接回答「发生了什么」，占用屏幕宽度少且靠边位置与展开方向一致，降低试错；拖动、展开提示集成在连续的形状里。B 的辨识度更像应用图标，但只显示数字时信息价值较低，也较难让人联想到「向内展开的摘要列表」。如果用户希望更像桌面品牌贴纸、而非侧边工具，再选 B。

## 两方案共用的展开内容规范

- 展开内容内边距 12px，标题区高约 40px，组间距 12px；列表行最小高 **72px**，多行正文可扩展。动作区目标至少 36px 高，单行文字按钮加 8px 间距；键盘焦点可见。原文详情折叠区以正文自然高度为准，不截断关键信息。
- 内容顺序：标题（「待处理」+ 未读数/收起按钮）→ 紧急项 → 待办 → 新通知。紧急项仅在 `urgent` 为真时出现；待办与通知都按紧急优先、`deadline` 时间升序、随后原有顺序排列。无截止时间排在有截止时间之后。相同紧急度不重排任意业务字段。
- 行内容：首行 `summary`，其次截止时间/来源 `deadline`、`source`，正文预览用 `text`；通知详情显示 `source` 群名与发送者（只有接口字段提供时才显示），不得臆造字段或补造说话人信息。标题最多两行后省略；正文预览最多两行，点开后完整显示。

## 配色、表面与暗色

- 复用当前页面 token：主要表面 `--paper`，次表面 `--paper-alt`，文字 `--ink`/`--muted`，分隔/描边 `--line`，主操作和已选态 `--teal`/`--teal-soft`，截止临近提示 `--amber`/`--amber-soft`，真正错误或未读徽标 `--red`/`--red-soft`。本设计不单独定义另一套色板；承载页面需从当前主题继承这些变量。
- 未读徽标使用 `--red` 底色和对比充分的白字，详情里的「紧急」文字/图标与颜色同时出现。普通通知和待办不使用红色装饰。
- 圆角：方案 A 胶囊 24px，方案 B 卡片 18px；A/B 的徽标 999px，展开窗口 12px，列表行 8px，小标签 999px，控制按钮 7px。描边 1px `--line`。
- 阴影三层：收起窗口 `0 4px 12px rgba(0,0,0,.18)`；展开窗口 `0 12px 32px rgba(0,0,0,.22)`；面板内行 `0 2px 6px rgba(0,0,0,.06)`。暗色主题统一提高阴影不透明度至约 .35、不要改变彩色 token 语义；暗色底面、边界、文字由群务台既有主题变量提供。系统色彩主题变化时浮窗同步，不固定浅色截图。

## 动效规格

动效均为状态变化的短反馈；页面内容动画只用 `transform`、`opacity`，颜色/边框可直接切换。宿主对同一 Win32 窗口的边界调整是展开/收起的几何变化，不由 CSS 逐帧改内容 `width/height`。曲线沿用仓库现有 Taste 约定：进入 `cubic-bezier(.2,.8,.2,1)`，退出 `cubic-bezier(.4,0,1,1)`。

| 场景 | 动画 | 时长与曲线 |
|---|---|---|
| 展开浮窗 | A/B 同一窗口向内侧展开到 360px 并按内容调整高度；窗口固定角锚点，内容区 `opacity:0→1`、`translateY(6px) scale(.98)→0/1`，不新建窗口 | 窗口由宿主协调调整；内容 200ms，`cubic-bezier(.2,.8,.2,1)` |
| 收起浮窗 | 内容区 `opacity:1→0`、`translateY(0) scale(1)→4px/.98`，内容隐藏后同一窗口回到 A 的 64×148px 或 B 的 72×72px | 内容 140ms，`cubic-bezier(.4,0,1,1)`；窗口边界由宿主调整 |
| 拖动吸附 | 通过固定顶部 10px 拖动纹/手柄拖动；拖动时跟手，不做持续弹动；松手移动至最近屏幕边缘，完成最多 10px 的视觉回弹（无过冲） | 240ms，`cubic-bezier(.2,.8,.2,1)` |
| 角标变化 | 数字变化时短促 `scale(.88)→1`，数字文字即时更新；不做循环呼吸/跳动 | 160ms，`cubic-bezier(.2,.8,.2,1)` |
| 完成反馈 | 仅服务端确认成功后，勾选图标绘制并将行轻移 4px、淡出；先更新角标，行再移出，避免计数与列表竞争 | 图标 180ms `ease-out`；行 180ms `cubic-bezier(.4,0,1,1)` |

**系统减少动态效果**（`prefers-reduced-motion: reduce`）：A/B 两方案均关闭所有位移、缩放、吸附回弹和图标绘制；内容立即显隐或仅做不超过 80ms 的透明度变化；宿主仍调整同一个窗口的边界但不做过渡；拖动仍然可用但落点直接贴边；完成通过勾选符号、文字状态和角标即时变化表达。动效不能是唯一状态信号。

## 交互时序与状态

状态最小集合：`closed`、`open`、`dragging`、`hidden-fullscreen`。面板打开时由焦点/点击外部规则决定收起；`hidden-fullscreen` 优先级最高，任何点击都不能让全屏中的浮窗出现。首次提醒设置为一次性设置向导，默认选中「安静」，完成选择后关闭并由设置页再次进入；不得在原型中假装保存成功。

1. **点击收起卡片 → 展开**：仅在 `closed` 时点击卡片内图标/角标；状态转 `open`，宿主扩展同一个无边框窗口；内容区显现并把键盘焦点放到面板标题/首个可操作控件；读屏宣告「待处理列表，N 条」。重复点击主按钮收起。
2. **点通知/待办 → 看详情**：点击摘要行或用 Enter/Space，展开同一行详情；详情只展示现有数据 `summary/text/deadline/urgent/source`，通知说话人/群组只在后端真实提供时展示。再次激活该行收起详情。动作按钮操作不触发详情切换。
3. **完成 / 稍后 / 忽略**：用户显式点击具体动作后发起对应已有业务操作；请求期间该行动作禁用并有文字进行态。仅成功响应后更新状态/角标并播放完成反馈；失败保留原行、恢复按钮并展示可读错误与重试入口。稍后与忽略不是完成，不播放勾选成功反馈。
4. **拖动 → 松手吸附**：在固定的顶部 10px 拖动条按住拖动；超过 5px 才进入 `dragging`，并关闭点击激活，阻止误开面板。拖动期间窗口保持收起态并跟随指针；松手后依据窗口边界到四边的距离吸附到最近一边，纵向位置限制在可用区域内，避开系统任务栏/窗口客户区。位置按窗口坐标保存并在下次显示时恢复；无可用持久化 API 时退回当前会话位置，不阻止使用。
5. **点击外部 → 收起**：`open` 时，点击窗口之外且不是窗口本身，转 `closed`；点击窗口内的链接/按钮不算外部点击。Escape 收起并把焦点还给收起态主按钮；焦点离开 WebView 是否自动收起由宿主确认，不应仅因面板内部焦点移动而关闭。
6. **全屏切换 → 隐藏**：宿主检测应用全屏后，立即转 `hidden-fullscreen` 并关闭同一窗口；还原普通窗口后回到上次 `closed/open` 之前的侧边位置，但默认从 `closed` 恢复，避免全屏退出时弹窗遮挡。若无法可靠检测全屏，宿主明确报告不可用，不靠页面尺寸猜测。
7. **提醒设置**：首次出现三项单选：安静（默认）、系统气泡、气泡+提示音。用户选择并确认后才应用；可从群务台设置重新打开。声音不得作为唯一通知通道；不自动播放测试音。

## 原型数据边界

原型中每项仅用 `summary`、`text`、`deadline`、`urgent`、`source` 字段；不模拟 URL、头像、发言人 ID、API 方法、接口响应或持久化。待后端接口字段清单确认后再调整模型。
