# 群务台 notice-hub · 项目说明

一个跑在你自己电脑上的小服务：把指定 QQ 群、微信群、钉钉群、学习通课程里的通知挑出来，变成网页上的待办清单和手机日历里的日程。

整个程序是单个 Python 进程，自带网页界面，数据存在本机 SQLite 里。没有云端账号，没有中转服务器。

---

## 一、它解决什么问题

群里的通知混在闲聊里，没人愿意一条条翻：报名截止、开会时间、要交的作业、要点的链接，常常是看到时已经过期。

群务台做三件事：读群消息 → 判断哪条是通知 → 变成「今天 / 本周 / 已过期」的待办；能给确定的，就顺手写上截止时间。手机可以订阅日历，也可以打开一个为手机做的网页看板。

## 二、能做的和不能做的

能做的：

- **读多个来源**：QQ 群（经 NapCat）、微信群（读本机微信数据库）、钉钉群、学习通课程通知、群文件与图片里的文字。
- **过滤闲聊**：规则 + 可选的大模型判断，只把通知、任务、截止时间留下。
- **待办台**：网页上看今天、本周、已过期；改状态、稍后提醒、转成日程、删除。
- **通知收件箱**：原文、附件原图都在，能一键转成待办。
- **手机日历订阅**：`/calendar.ics` 给一个地址，手机日历自己拉取；局域网或公网都行，公网默认走 Cloudflare（不用注册、不用域名），要固定地址可切 Tailscale。
- **推送**：Webhook、Server 酱、PushPlus、WxPusher、钉钉机器人、企业微信。
- **手机 App**：扫码连上这台电脑，看概览与待办；离线时显示上次同步时间。
- **自动更新**：稳定/测试两条通道，更新包校验 SHA-256，清单签名校验。

不做的：

- 不发言、不主动加好友、不改群设置——只读。
- 不上传你的数据到任何服务器。只有你自己配了模型或推送通道时，那部分内容才会发给你选的那家服务商。

## 三、怎么跑起来

三种方式，按省事程度排：

1. **Windows 安装包（推荐）**：下载 `QQ-Notice-Hub.zip`，解压到任意目录（例如 `F:\notice-hub`），双击 `QQ-Notice-Hub.exe`。第一次会引导你装 NapCat、扫码登录、选群。
2. **源码运行**：装 Python 3.12+，`pip install -r requirements.txt`，然后 `python main.py run`。Windows 上还可以用 `install-task.ps1` 注册开机自启。
3. **手机 App**：装 `noticehub-app.apk`，扫电脑网页上「设置 → 手机」里的二维码。

装完第一次要做的四步：选要订阅的群 → （可选）配模型 → 配推送通道 → 把日历订阅地址加进手机日历。缺哪一步，网页顶部横幅会告诉你还差什么。

## 四、升级

- 网页「设置 → 版本更新」点检查更新，下载、校验、安装一次做完。
- 或者直接下新版压缩包，覆盖解压到原目录——`data/`、`.env`、`logs/` 都在里面，不会被覆盖掉。
- 两条通道：`NOTICEHUB_UPDATE_CHANNEL=stable`（只升正式版）或 `beta`（跟测试版）。稳定通道按 tag 过滤，正式版用户不会被推进测试版。

## 五、你的数据在哪

| 东西 | 位置 |
|---|---|
| 消息、待办、附件记录 | `data/digest.sqlite3` |
| 附件原图与文件 | `data/attachments/` |
| 数据库每日快照（留 7 份） | `data/snapshots/` |
| 配置 | 安装目录下 `.env` |
| 日志 | `logs/` |

备份就备份 `data/` 和 `.env`。数据库坏了会自动隔离成 `.corrupt-<时间戳>` 再重建，不会一崩到底。

## 六、配置项

全部走环境变量或 `.env`，前缀 `NOTICEHUB_`。旧的 `QQ_DIGEST_*` 仍然会被读取（启动时提示一次），所以老安装升级后不会起不来。

两类配置：

- **常用项**在网页设置页里改，改完直接写回 `.env` 并生效，不用重启。
- **冷门项**（并发、超时、实验功能开关）直接编辑 `.env`，重启生效。

设置页的「配置体检」会列出每个关键项的当前值、来源（环境变量 / `.env` / 默认值 / 自动探测）以及有没有被别的来源顶掉——端口冲突这类问题一眼能看出来。

完整清单见 `docs/api.md` 的「配置项」一节和 `.env.example`。

## 七、代码结构

```
main.py                    命令行入口（run / tick / preview / doctor / stats / tasks / ...）
qq_digest.py               文本分析内核：解析消息、抽时间、判通知、调模型精炼
noticehub/
  bootstrap/               启动装配：命令行、读 Settings、建 Store、挑日志
  domain/                  纯逻辑：时间、消息与事件模型、规则、资格判断（不碰 IO）
  application/             用例编排：收消息、附件、排期、任务、日历、订阅
  ports/                   接口定义：时钟、通知器（domain/application 只依赖它）
  infrastructure/          实现：SQLite 存储、时钟与通知的具体实现
  adapters/qq/onebot.py    QQ 的 OneBot 协议适配
  webapp.py                HTTP 服务与全部网页接口
  routes.py                路由表
  service.py               一轮 tick 的编排（收消息 → 判断 → 落库 → 推送 → 提醒）
  store.py 等              兼容再导出层（实现已分居各层，保留旧导入名）
  web_static/              页面模板、样式脚本、图标与 PWA 清单
  push.py / receiver.py    推送通道、收消息入口
  updater.py               自动更新
  wechat_receiver.py       微信
  dingtalk_receiver.py     钉钉
  chaoxing_receiver.py     学习通
tests/                     全量门禁用例
tools/                     发版、同步 wiki、诊断脚本
packaging/                 PyInstaller 打包与安装包组装
android/                   手机 App（Gradle 工程）
docs/                      文档、wiki 源、架构图
```

分层意图很简单：`domain` 不依赖任何外部东西，`application` 只编排，`infrastructure` 才碰磁盘和网络。所以核心判断逻辑可以在没有网络、没有数据库的情况下跑测试。顶层的 `store.py`、`timeutil.py` 这类薄壳是重写过程留下的兼容再导出，不是设计意图。

## 九、开发与验收

```powershell
# 全量测试（需要几分钟）
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -t .

# 只跑某个模块
.\.venv\Scripts\python.exe -X utf8 -m unittest tests.test_store
```

规矩写在 `AGENTS.md`：断言是契约，不许为了让测试变绿而放宽断言、删用例或 skip；改了 `x.py` 必须同步改 `tests/test_x.py`；界面改动必须自己截图看过；每次改动至少更新 `docs/wiki/changelog.md` 的「未发布」小节。
